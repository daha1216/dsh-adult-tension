## 2. 归因结论（按扣减顺序复算）

**Δ口径（A → A'）= +43 案例，最大的一段。** 同一批 80 份转写、同样修复前的素材与 v2 协议，只换评分者与简报（Codex v2 口径 → glm-5.3 复核口径），案例 36 → 79、续写均值 7.80 → 9.35（+1.55）、零分维 23 → 1、扣分点 582 → 156。落差集中在 `natural_expression`（273 → 136）与 `character_credibility`（75 → 0）。

**Δ协议（A' → B'）= −35 案例。** 同一评分者、同样修复前素材，协议由 v2 升到 v3，案例 79 → 44、续写均值 9.35 → 9.15、零分维 1 → 35、扣分点 156 → 212：**探针变严后分数是下降的**，下降全部落在 `world_specificity`（2 → 77）与 `consequence_continuity`（3 → 82）。

**Δ素材（B' → C）= +35 案例，是修复的净效果。** 协议与评分口径相同，只有素材从修复前换到修复后：案例 44 → 79、续写均值 9.15 → 9.66（+0.51）、零分维 35 → 1、扣分点 212 → 88；差异同样集中在 `world_specificity`（77 → 2）与 `consequence_continuity`（82 → 29）。

**净效应恰好抵消：A'（79）≈ C（79）。** 所以第二轮报告的「36 → 79」不能读作素材修复或协议改版的成果——它主要是**评分口径变化**（+43）；素材修复的真实作用是「把更严探针下的 44 拉回 79」，即**修复掉的正是严格探针专门要抓的失败模式**（凭空状态变化/现场编造安排类硬阻断），而不是把分数从 36 提到 79。

## 3. 为什么 Δ协议 是负的（机制）

v3 把「续写①当回合就要把可被引用的具体安排写清、写到板面/纸面/当面说明都算」写进请求与规则串，等于给探针新增了一个可失败点：模型要么根本不写（`meaningful_choices` / `natural_expression` 扣分），要么当场编一条（`world_specificity` 0 分硬阻断）。B' 的 35 例硬阻断与 77 分 ws 扣分就是这么来的；A' 的同一批判分只有 1 例零分维、ws 扣 2 分，说明 v2 协议**根本没测这件事**。

由此也解释了 v4 追加第 9 条（被异议条款必须能在前文正文逐字找到）的必要性：把「现场编一条再声称旧有」从模型自由发挥变成明确违规，既保留探针灵敏度、又不让它变成不可判定的模糊扣分。协议 v3/v4 的收益是**探针灵敏度**（能测出 v2 测不出的东西），不是分数。

## 4. 口径限制（横比时必须一起读）

- Δ口径 同时换了评分者模型与简报模板（Codex + v2 简报 → glm-5.3 + 复核简报），数值是「复核侧整体变化」的幅度，无法再拆成模型与模板两段。
- B' 与 C 的评分驱动不同：B' 是本轮 `scripts/review_playtest.py`（agent 式：先读简报与转写再写 review），C 是第二轮流程（reviewer 字段同为 glm 系 `glm-independent-review-v3`，驱动未留档）。两者差距集中在 35 例硬阻断（ws=0），流程差异不足以解释这个量级。
- A' 对 v2 转写只套用复核侧校准 1/2/6/7/8（已声明动作不算代行、appellations 称呼不算错、ne 扣分须有具体依据、blocking 只放真阻断）与第 6 条凭空事实；不套用只对 v3 规则成立的 3/4/5 条（时间词一致、出口不重复、活动每回合推进）。因此 **Δ协议 是该口径下的下界**。
- 每案例只有一份转写（seed 11、单次生成），案例级差异含采样噪声；本报告的读法是「批间差异的方向与量级」，不是逐案因果。

## 5. 与第二轮报告的差异

第二轮报告把 36 → 79 一并记在「协议 v3 + 框架/模板定点修」名下，未拆分素材与口径；本轮补评后可以确定这个记法是错的：口径段 +43、协议段 −35、素材段 +35。`implementation_report.md` §1.1 的 9.31/7.78、§1.3 的分布 30/48/1/1 已勘误为 9.34/7.80 与 24/50/5/1；本轮结论（含「必须 80/80」的验收决策）记在该文件 §8。
