# 世界运转

本文件只负责时间、Tier 追算、离屏行动、事件、关系传播和历史压缩；运行时事务顺序以 `SKILL.md` 为准，存档字段以 `references/状态总结.md` 为准。

## 时间

时间字段（`clock`/`previous_clock`/`delta_t`/`delta_human`）的格式、时区与“开局相等、
`delta_t=0`”等取值约束以 `references/状态总结.md` 为准。本文件只规定推进行为：玩家明确
指定时间时直接采用；否则普通行动默认推进 1–15 分钟，取完成动作所需的最小合理时间，
不擅自跨天。时间变化时先把旧 `clock` 写入 `previous_clock`，再写新 `clock` 与对应 `delta_t`。
「继续」必须让时钟变化。禁止连续多个玩家回合 `clock` 仍等于开局时刻。

小时间跨度只处理时钟、短期情绪和自然衰减。过夜、数日或明确快进时按 Tier 追算。
对方已离场时的「继续」即使跨度很小，也要执行一次最小离屏追算：到期事件、该 NPC 的一个离屏节拍、关系衰减。

`meta.simulation` 是离屏追算总开关：为 `true`（默认）时按本文件正常执行 Tier2/Tier3 的离屏行动、世界事件与传播；为 `false` 时只处理时钟、到期定时事件和持续状态自然变化，不生成任何离屏 NPC 行动与传播，用于纯双人封闭场景或需要冻结世界背景时。

## Tier

| Tier | 追算范围 |
|---|---|
| 1 | 时间、持续状态、死线和定时事件 |
| 2 | Tier1 + 活跃 NPC 离屏行动 + 世界事件 |
| 3 | Tier2 + 关系网络传播、组织反应和远程后果 |

活跃 NPC 是当前场景参与者、当前 pending 事件直接涉及者、最近 3 个玩家回合内行动过的角色，或因传播抵达而被激活的角色。其他角色不生成离屏行动，除非已有事件重新激活。

`meta.simulation` 是 Tier 之上的总闸：为 `false` 时无论 `meta.tier` 记为几，追算实际只执行 Tier1 范围（时钟、到期定时事件、持续状态自然变化），不生成任何离屏行动、世界事件、传播与转折；`tier` 字段本身不被改写，恢复推演后按原 Tier 继续。

## 中期剧情转折

### 信息类

新证据出现、误传扩散、关键记录缺页

### 人事类

盟友松动、旧人归来、关键岗位换人

### 资源类

断供、替代品出现、藏匿资源被发现

### 制度类

例外被撤、审查突至、规则临时收紧

### 时限类

死线提前、行动窗口缩短、预约被改期

### 关系类

两名 NPC 私下接触、立场被试探、秘密互换

### 意外类

事故、天气毁掉计划、交通或通讯中断

硬规则：

1. 仅 `meta.simulation` 为 true 且为 Tier2/Tier3 的快进可注入转折；Tier1 或 `simulation=false` 不注入。
2. 转折必须经由事件队列落账，带稳定 `semantic_key`；同一含义不得换 ID 重建。
3. 转折必须与既有张力引擎、活跃 NPC 或 pending 事件形成可说明的因果连接，不得凭空替换当前冲突。
4. 转折只改变信息、人员、资源、制度、时限、关系或计划条件；不替玩家作关键选择。

## 离屏行动

活跃 NPC 的判定见 `## Tier`。每个活跃 NPC 在一次追算中最多生成一项显著行动，且须遵守自主冷却。显著行动必须改变位置、资源、关系、信息或事件；普通移动、等待和重复劳动不单独记为自主动作。

```text
<npc_id>｜<时间段>｜<地点>｜<行动>｜<留下或改变的事件ID>
```

行动必须来自该角色的身份、目标、已知信息和资源，不得重新抽取身份。离屏行动不能替玩家作出关键选择。自主冷却按玩家回合计算，不因世界时间快进而重置；跨越多个回合时仍按已有 `recent_turns` 判断。

## 事件结构

```yaml
- id: evt-001
  semantic_key: "审议会要求公开答复"
  source: turn:3
  created_turn: 3
  kind: timed
  trigger: "2026-07-13T08:00:00+08:00"
  due_at: "2026-07-13T08:00:00+08:00"
  status: pending
  consequence: "审议会要求公开答复"
  hook: false
  probability: null
```

`id` 是稳定事件 ID，`semantic_key` 是用于去重的稳定语义键；同一含义事件不得通过更换 ID 重建。`source` 必须是 `type:id`：`system:<id>`、`turn:<n>`、`npc:<npc_id>` 或 `world:<id>`；其中 npc 来源必须引用现有角色。`due_at` 必须是带时区的 ISO 8601 时点；没有固定时点的条件或概率事件写 null，不得以空字符串替代。`kind` 使用 `immediate|near|far|timed|probabilistic`。所有事件均必须带 `probability`：仅 `probabilistic` 使用 (0, 1] 数值，其他 kind 写 null。已解决事件改为 `resolved`，被明确取消则改为 `cancelled`，不得删除后重新创建同一含义事件。

`probabilistic` 事件的 `probability` 是必填数值，保证判定过程可恢复；其他 kind 的同名字段必须为 null。`checked_turns` 仍为可选扩展，用于记录已判定但未命中的玩家回合，避免同一窗口重复判定。

```yaml
- id: evt-006
  semantic_key: "旧客户突然回城"
  source: turn:4
  created_turn: 4
  kind: probabilistic
  trigger: "玩家仍在城内且未清账"
  due_at: null
  probability: 0.5
  checked_turns: [5, 7]
  status: pending
  consequence: "旧客户回城施压"
  hook: false
```

## 处理顺序

本节是 `SKILL.md`「每回合事务」第 2 步（生成候选→追算）的内部子流程，只规定追算内部的执行顺序；外层事务顺序仍以 `SKILL.md` 为准。

1. 更新时间。
2. 兑现到期定时事件。
3. 兑现满足条件的 near/far 事件。
4. 按 `probability` 与 `trigger` 条件判定 probabilistic 事件；命中则兑现，未命中把当前回合追加进 `checked_turns` 并保持 pending。同一追算窗口内不重复判定。
5. 处理持续状态自然变化。
6. Tier2 生成离屏行动和世界事件。
7. Tier3 沿已存在的顶层关系边传播信息；没有关系边时不得自动传播精确信息。人物卡中的生成期关系说明不得覆盖 `relationships` 的正式边。
8. 以稳定 ID 和 `semantic_key` 去重，核对 `source`、`due_at` 后提交。

## 关系图

关系边的存档字段（`source/target/type/channel/trust/last_updated_turn`，`trust` 取
-5..+5 整数）以 `references/状态总结.md` 与 `scripts/validate_state.py` 为准，本文件不复述。
本节只规定传播语义：

传播速度由渠道、信任和时间跨度共同决定；传播内容只能来自发送方**已知信息**，且必须保留渠道造成的失真。信任越低传播越慢、越易截断或曲解。未建立边的角色之间不得自动传播精确信息——至多经流言网络产生高失真的模糊信息，且仍需一条可说明的到达路径。

| 渠道 | 速度 | 失真 |
|---|---|---|
| 同住或同组 | 数小时 | 低 |
| 同事组织 | 当天 | 中 |
| 私人通信 | 视可达性 | 低至中 |
| 流言网络 | 1-3 天 | 高 |
| 专业链条 | 视流程 | 低 |
| 敌对监视 | 视投入 | 低，但可能故意误导 |

## 压缩

只压缩已解决事件和不再驱动人物反应的旧记忆。不可压缩字段的完整清单以
`references/状态总结.md` 为唯一来源。本文件只强调一条追算约束：凡仍可能被未来追算
读取的对象——pending 事件、远程钩子、活跃死线、关系图活跃边——在被
`references/状态总结.md` 判定可压缩之前必须保持原样可追算，不得因“历史已久”提前折叠。
