# 世界运转

本文件只负责时间、Tier 追算、离屏行动、事件、关系传播和历史压缩；运行时事务顺序以 `SKILL.md` 为准，存档字段以 `references/状态总结.md` 为准。

## 时间

保存当前时间、上次定位时间和本次 `delta_t`。`clock` 与 `previous_clock` 使用 ISO 8601 字符串，`delta_t` 使用非负整数秒，`delta_human` 仅用于人类可读显示。玩家明确指定时间时直接采用；否则取完成动作所需的最小合理时间，不擅自快进。

小时间跨度只处理时钟、短期情绪和自然衰减。过夜、数日或明确快进时按 Tier 追算。时间变化必须先更新 `previous_clock`，再写入新的 `clock` 和 `delta_t`。开局或无时间流逝时，`previous_clock` 与 `clock` 取相同值、`delta_t` 为 0。

`meta.simulation` 是离屏追算总开关：为 `true`（默认）时按本文件正常执行 Tier2/Tier3 的离屏行动、世界事件与传播；为 `false` 时只处理时钟、到期定时事件和持续状态自然变化，不生成任何离屏 NPC 行动与传播，用于纯双人封闭场景或需要冻结世界背景时。

## Tier

| Tier | 追算范围 |
|---|---|
| 1 | 时间、持续状态、死线和定时事件 |
| 2 | Tier1 + 活跃 NPC 离屏行动 + 世界事件 |
| 3 | Tier2 + 关系网络传播、组织反应和远程后果 |

活跃 NPC 是当前场景参与者、当前 pending 事件直接涉及者、最近 3 个玩家回合内行动过的角色，或因传播抵达而被激活的角色。其他角色不生成离屏行动，除非已有事件重新激活。

## 中期剧情转折

快进时可运行 `python scripts/roll_opening.py --twist`，抽取 2-3 个转折方向；它只提供方向，不直接改写剧情或状态。

### 信息类

新证据出现、误传扩散、关键记录缺页

### 人事类

盟友松动、旧人归来、关键岗位换人

### 资源类

断供、替代品出现、藏匿资源被发现

### 制度类

例外被撤、审查突至、规则临时收紧

### 时限类

死线提前、行动窗口缩短、预约被改期

### 关系类

两名 NPC 私下接触、立场被试探、秘密互换

### 意外类

事故、天气毁掉计划、交通或通讯中断

硬规则：

1. 仅 Tier2/Tier3 的快进可注入转折；Tier1 不注入。
2. 转折必须经由事件队列落账，带稳定 `semantic_key`；同一含义不得换 ID 重建。
3. 转折必须与既有张力引擎、活跃 NPC 或 pending 事件形成可说明的因果连接，不得凭空替换当前冲突。
4. 转折只改变信息、人员、资源、制度、时限、关系或计划条件；不替玩家作关键选择。

## 离屏行动

每个活跃 NPC 在一次追算中最多生成一项显著行动，且须遵守自主冷却。显著行动必须改变位置、资源、关系、信息或事件；普通移动、等待和重复劳动不单独记为自主动作。

```text
<npc_id>｜<时间段>｜<地点>｜<行动>｜<留下或改变的事件ID>
```

行动必须来自该角色的身份、目标、已知信息和资源，不得重新抽取身份。离屏行动不能替玩家作出关键选择。自主冷却按玩家回合计算，不因世界时间快进而重置；跨越多个回合时仍按已有 `recent_turns` 判断。

## 事件结构

```yaml
- id: evt-001
  semantic_key: "审议会要求公开答复"
  source: turn-3
  created_turn: 3
  kind: timed
  trigger: "2026-07-13T08:00:00+08:00"
  due_at: "2026-07-13T08:00:00+08:00"
  status: pending
  consequence: "审议会要求公开答复"
  hook: false
```

`id` 是稳定事件 ID，`semantic_key` 是用于去重的稳定语义键；同一含义事件不得通过更换 ID 重建。`kind` 使用 `immediate|near|far|timed|probabilistic`。已解决事件改为 `resolved`，被明确取消则改为 `cancelled`，不得删除后重新创建同一含义事件。

## 处理顺序

1. 更新时间。
2. 兑现到期定时事件。
3. 兑现满足条件的 near/far 事件。
4. 按触发概率与条件判定 probabilistic 事件；命中则兑现，未命中保持 pending。
5. 处理持续状态自然变化。
6. Tier2 生成离屏行动和世界事件。
7. Tier3 沿已存在的关系边传播信息；没有关系边时不得自动传播精确信息。
8. 以稳定 ID 和 `semantic_key` 去重并提交。

## 关系图

```text
source_id -> target_id | 类型 | 渠道 | 信任(-5..+5) | last_updated_turn
```

传播速度由渠道、信任和时间跨度共同决定；传播内容只能来自发送方已知信息，且应保留渠道造成的失真。未建立边的角色之间不得自动传播精确信息。

| 渠道 | 速度 | 失真 |
|---|---|---|
| 同住或同组 | 数小时 | 低 |
| 同事组织 | 当天 | 中 |
| 私人通信 | 视可达性 | 低至中 |
| 流言网络 | 1-3 天 | 高 |
| 专业链条 | 视流程 | 低 |
| 敌对监视 | 视投入 | 低，但可能故意误导 |

## 压缩

只压缩已解决事件和不再驱动人物反应的旧记忆。始终保留：

- pending 事件
- `[钩]` 远程事件和 `hook: true` 记录
- 活跃死线
- 角色自主冷却
- active 玩家边界
- 当前场景同意和安全状态
- 关系图活跃边
- 最近一次完整 checkpoint
