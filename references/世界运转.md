# 世界运转

本文件只负责时间、Tier 追算、离屏行动、事件、关系传播和历史压缩；运行时事务顺序以 `SKILL.md` 为准，存档字段以 `references/状态总结.md` 为准。

本文件只承载语义：转折词条等数据本体在 `scripts/data/twists.yaml`，脚本不解析本文件，章节标题可自由调整。

## 执行责任

模型负责根据活切片判断本回合要发生的叙事结果，并生成最小 patch；脚本负责把结果确定性地落盘、校验和硬升级。模型不得直接改写 `state.yaml`，脚本也不会替模型凭空生成 NPC 行动、世界事件或关系传播。

| 工作 | 模型 | 脚本 |
|---|---|---|
| 普通回合或深度回合判断 | 先判定 | 根据结构变化、时间跨度和 checkpoint 硬升级 |
| 时间推进、事件状态、压力种子 | 提供意图 | 计算、到期处理、重指与校验 |
| 离屏行动、世界事件、关系传播 | 生成因果结果 | 检查 `simulation` 闸门并落盘 |
| 概率事件 | 请求 `roll: true` | 按稳定输入抽取并记录结果 |
| 转折注入 | 运行 `--twist` 并提交标记 | 防重复、记录次数和校验 |

## 时间

时间字段（`clock`/`previous_clock`/`delta_t`/`delta_human`）的格式、时区与“开局相等、
`delta_t=0`”等取值约束以 `references/状态总结.md` 为准。本文件只规定推进行为：

| 时间跨度 | 处理方式 |
|---|---|
| 1–15 分钟 | 普通回合，处理当前动作、必要反应和最小状态变化 |
| 16–59 分钟 | 短快进，至少按深度回合检查事件和离屏影响 |
| 60 分钟以上或跨天 | 完整追算；脚本自动触发深度 checkpoint |

玩家明确指定时间时采用其结果，但不得倒流或把正数时间写入 `advance_turn: false` 的元指令；未指定时普通行动默认推进完成动作所需的最小合理时间，通常为 1–15 分钟，不擅自跨天。时间变化时先把旧 `clock` 写入 `previous_clock`，再写新 `clock` 与对应 `delta_t`。「继续」必须让时钟变化。

小时间跨度只处理时钟、短期情绪和自然衰减。过夜、数日或明确快进时按 Tier 追算。
对方已离场时的「继续」即使跨度很小，也要执行一次最小离屏追算：到期事件、该 NPC 的一个离屏节拍、关系衰减。离屏追算总闸见 `## Tier`。

## Tier（追算级别）

| Tier | 追算范围 |
|---|---|
| 1 | 时间、持续状态、死线和定时事件 |
| 2 | Tier1 + 活跃 NPC 离屏行动 + 世界事件 |
| 3 | Tier2 + 关系网络传播、组织反应和远程后果 |

Tier 是模型对追算范围的计划标签，不是可绕过脚本校验的权限。活跃 NPC 是当前场景参与者、当前 pending 事件直接涉及者、最近 3 个玩家回合内行动过的角色，或因传播抵达而被激活的角色。其他角色不生成离屏行动，除非已有事件重新激活。

`meta.simulation` 是 Tier 之上的总闸：为 `false` 时无论 `meta.tier` 记为几，追算实际只执行 Tier1 范围（时钟、到期定时事件、持续状态自然变化），不生成任何离屏行动、离屏世界事件、关系传播与转折。提交器会拦截 `autonomy_now`、离屏 `world:` 事件、传播标记和 `twist_generate`；玩家当前动作导致的直接事件与关系变化仍可提交。`tier` 字段本身不被改写，恢复推演后按原 Tier 继续。

## 中期剧情转折

第一次跨天且 `meta.simulation` 为 true 时先运行 `python scripts/roll_opening.py --twist`，抽取 2-3 个转折方向；它只提供方向，不直接改写剧情或状态，经 `events_add` 落地，并在同一 patch 里提交 `twist_generate: {reason: first_cross_day}`。自动转折同一局只生成一次；玩家明确要求新转折时使用 `reason: player_requested`，每次都必须形成新的事件语义键，不得覆盖旧转折。

转折词条池在 `scripts/data/twists.yaml`，固定七类且顺序不变：信息类、人事类、资源类、制度类、时限类、关系类、意外类；类内条目可自由增删，类别行为画像在 `scripts/data/twist_profiles.yaml`，改完跑 `python scripts/check_content.py` 体检。

硬规则：

1. 仅限跨天首夜且推演开启时自动注入（`simulation=false` 跳过）；快进/跨天由脚本自动触发完整 checkpoint。
2. 转折必须经由事件队列落账，带稳定 `semantic_key`；同一含义不得换 ID 重建。
3. 转折必须与既有张力引擎、活跃 NPC 或 pending 事件形成可说明的因果连接；只改变信息、人员、资源、制度、时限、关系或计划条件，不替玩家作关键选择。
4. `world.twist_state.generated_count` 是防重复记录；没有该字段视为从未生成，首次标记后由脚本维护。

## 离屏行动

活跃 NPC 的判定见 `## Tier`。每个活跃 NPC 在一次追算中最多生成一项显著行动，且须遵守自主冷却；一次跨越多个自然日的快进也不得为同一 NPC 生成超过每个追算窗口一项显著行动。显著行动必须改变位置、资源、关系、信息或事件；普通移动、等待和重复劳动不单独记为自主动作。

离屏追算按“每个活跃 NPC 一个行动槽”处理：先按当前 pending 事件和角色目标排序，再检查 `autonomy.cooldown_until`；冷却中的角色跳过本窗口，不为了填满行动槽强行生成事件。玩家当前动作、玩家已明确要求的换场或直接关系变化不算离屏行动，不受 `simulation=false` 的离屏闸门影响。

```text
<npc_id>｜<时间段>｜<地点>｜<行动>｜<留下或改变的事件ID>
```

行动必须来自该角色的身份、目标、已知信息和资源，不得重新抽取身份。离屏行动不能替玩家作出关键选择。自主冷却按玩家回合计算，不因世界时间快进而重置；口径与登记方式见 `SKILL.md`「NPC 决策」第 6 条，跨越多个回合时仍按已有 `recent_turns` 判断。

## 事件结构

```yaml
- id: evt-001
  semantic_key: "审议会要求公开答复"
  source: turn:3
  created_turn: 3
  kind: timed
  trigger: "2026-07-13T08:00:00+08:00"
  due_at: "2026-07-13T08:00:00+08:00"
  status: pending
  consequence: "审议会要求公开答复"
  hook: false
  probability: null
```

`id` 是稳定事件 ID，`semantic_key` 是用于去重的稳定语义键；同一含义事件不得通过更换 ID 重建。`source` 必须是 `type:id`：`system:<id>`、`turn:<n>`、`npc:<npc_id>` 或 `world:<id>`；其中 npc 来源必须引用现有角色。`due_at` 必须是带时区的 ISO 8601 时点；没有固定时点的条件或概率事件写 null，不得以空字符串替代。`kind` 使用 `immediate|near|far|timed|probabilistic`。所有事件均必须带 `probability`：仅 `probabilistic` 使用 (0, 1] 数值，其他 kind 写 null。`probability` 是命中阈值，不是模型自由发挥的结果。

**生命周期与落盘通道**：已解决事件经 patch 键 `events_resolve` 改为 `resolved`，明确取消经 `events_cancel` 改为 `cancelled`——两种情况下事件都**保留在队列中**，不得物理删除后重建同一含义事件（`resolved_summary` 只是摘要镜像）。字段修订用 `events_update`（可改 `trigger`/`due_at`/`consequence`/`probability`/`hook`；`id`/`semantic_key`/`kind`/`source`/`created_turn` 不可改）；`events_resolve`/`events_cancel`/`events_update` 引用不存在的 ID 会提交失败。压力种子引用的事件被解决或取消时，`commit_turn.py` 自动把种子重指到同类 pending 事件，没有就置空。

事件状态转换固定为：

| 当前状态 | 条件 | 结果 |
|---|---|---|
| `pending` | `due_at` 到期，或 `trigger` 已满足 | `resolved` |
| `pending` | 明确不再发生或被后续结果取代 | `cancelled` |
| `pending` + 概率未命中 | `roll: true` 且尚未检查本回合 | 保持 `pending`，追加 `checked_turns` |
| `resolved` / `cancelled` | 任何普通回合 | 终态，不重复兑现 |

`resolved` 与 `cancelled` 不得互相转换；同一事件同一回合只能走一次状态转换。

`checked_turns` 是可选扩展，记录已判定但未命中的玩家回合，避免同一窗口重复判定；落盘走 patch 键 `events_update` 的 `checked_turn_add: true`（提交器把当前回合追加进该列表）。

### 概率事件

需要判定概率事件时，模型只在 `events_update` 中提交 `{id: <event_id>, roll: true}`，不要自行填写命中结果。提交器使用 `meta.event_seed`（缺失按 `0`）、事件 ID 和当前回合计算稳定值 `roll_value ∈ [0, 1)`：小于 `probability` 即命中并转为 `resolved`，否则把当前回合写入 `checked_turns` 并保持 `pending`。每次判定都会保存 `last_roll: {turn, value, outcome}`，同一事件同一回合不得重复抽取。

```yaml
- id: evt-006
  semantic_key: "旧客户突然回城"
  source: turn:4
  created_turn: 4
  kind: probabilistic
  trigger: "玩家仍在城内且未清账"
  due_at: null
  probability: 0.5
  last_roll: {turn: 5, value: 0.237, outcome: miss}
  checked_turns: [5, 7]
  status: pending
  consequence: "旧客户回城施压"
  hook: false
```

## 处理顺序

本节是 `SKILL.md`「每回合事务」第 2 步（预演）里、需要追算时的内部子流程；外层事务顺序仍以 `SKILL.md` 为准。

1. 更新时间。
2. 兑现到期定时事件。`commit_turn.py` 会把 `due_at` 已到的 pending 定时事件标为 resolved，结果句为「时限已到，尚未在场上兑现」；正文须交代可见后果，不得当没发生。
3. 兑现满足条件的 near/far 事件。
4. 按 `trigger` 条件筛选 probabilistic 事件，再用 `events_update` 的 `roll: true` 请求脚本抽取；命中自动转为 `resolved`，未命中自动追加 `checked_turns` 并保持 pending。同一追算窗口内不重复判定。
5. 处理持续状态自然变化。
6. Tier2 生成离屏行动和世界事件。
7. Tier3 沿已存在的顶层关系边传播信息；没有关系边时不得自动传播精确信息。人物卡中的生成期关系说明不得覆盖 `relationships` 的正式边。一回合涉及多条关系边时，`relationship_delta` 接受列表形式一次提交多条。`relationships` 当前按无向关系边存储，传播时仍须明确发送方、接收方和实际渠道。
8. 以稳定 ID 和 `semantic_key` 去重，核对 `source`、`due_at` 后提交。

## 关系图

关系边的存档字段（`source/target/type/channel/trust/last_updated_turn`，`trust` 取
-5..+5 整数）以 `references/状态总结.md` 与 `scripts/validate_state.py` 为准，本文件不复述。
本节只规定传播语义：

传播速度由渠道、信任和时间跨度共同决定；传播内容只能来自发送方**已知信息**，且必须保留渠道造成的失真。信任度越低，传播速度越慢、越容易被截断或曲解。未建立直接关系边的角色之间不得自动透传精确信息；即便经由流言网络扩散，也必须附带高失真与模糊化，且在叙事上具备可合理解释的流转路径。关系边只保留一条规范化的角色对，传播方向不改变边的归属。

| 渠道 | 速度 | 失真 |
|---|---|---|
| 同住或同组 | 数小时 | 低 |
| 同事组织 | 当天 | 中 |
| 私人通信 | 视可达性 | 低至中 |
| 流言网络 | 1-3 天 | 高 |
| 专业链条 | 视流程 | 低 |
| 敌对监视 | 视投入 | 低，但可能故意误导 |

关系变化通过 `relationship_delta` 提交：`trust` 始终表示增量并夹到 `-5..+5`；需要直接设定时使用 `trust_set`，不得再用大于 5 的数值猜测“增量还是绝对值”。未提供明确传播路径时，不得自动创建关系边。

## 压缩

只压缩已解决事件和不再驱动人物反应的旧记忆。「旧记忆」的判定口径：该记忆不再被任何活跃人物引用、不再影响任何 pending 事件或当前处境，且不存在未完成的关系传播、组织反应或远程钩子依赖，方可折叠；仍被引用的一律算「近期记忆」，不可压缩。不可压缩字段的完整清单以
`references/状态总结.md` 为唯一来源。本文件只强调一条追算约束：凡仍可能被未来追算
读取的对象——pending/cancelled 中仍被引用的事件、远程钩子、活跃死线、关系图活跃边——在被
`references/状态总结.md` 判定可压缩之前必须保持原样可追算，不得因“历史已久”提前折叠。
