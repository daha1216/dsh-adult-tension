# 加内容

给这套叙事引擎扩充素材、文案、题材要素的指南。**所有内容都在 `scripts/data/` 下的 yaml 文件里**，改内容不需要碰代码、也不需要在意文档格式。

## 总流程

1. 改对应的 yaml 文件（见下面两张对照表）。
2. 跑 `python scripts/check_content.py`——同步问题（比如新地点没配房间细节）会逐条列出。
3. 跑 `python -m pytest tests -q`——内容指纹测试会报警，这是故意的；确认改动是你想要的后，把失败信息里打印的新指纹填进 `tests/test_content_integrity.py` 的 `EXPECTED`。
4. 想直观看看效果：`python scripts/roll_opening.py --seed 42 --no-history` 看抽词条，`python scripts/build_opening.py --complete --seed 42 --out %TEMP%\probe.yaml --force` 看完整开局。

注意：池子内容变化后，同一个种子会抽出不同的开局——这是预期效果，不是故障。旧存档完全不受影响（存档裁判 `validate_state.py` 与内容数据无关）。

## 常规扩充对照表（只改 yaml）

| 我想加/改…… | 改哪个文件 | 还要同步什么 |
|---|---|---|
| 一个地点 | `pools.yaml`「时代与地点·地点」 | `locations.yaml` 加至少一条房间细节（缺了开局会报错）；如属时代专属硬锁地点，同步登记 `meta.location_eras`（键=地点名，值=配套时代列表，抽到时时代让路重抽） |
| 一个时代 | `pools.yaml`「时代与地点·时代」 | 新增时代时，`scripts/data/names.yaml` 的 `eras` 节若有对应分名池，键名必须与时代名逐字一致（`check_content.py` 强制，不一致报 ERROR）；可为新时代补专属分名池（姓 8 个 + 名 8–10 个，仿既有时代分名池格式），不补则回落通用名池 |
| 一类身份圈层 | `pools.yaml`「身份侧」 | `identities.yaml` 的 `npc` 下加至少一个具体身份；可选在 `pools.yaml` meta.identity_weights 配抽取权重（不配按 8 计） |
| 某圈层下的一个具体身份 | `identities.yaml` | 无 |
| 一种处境（她正扛的事） | `pools.yaml`「处境侧」 | `templates.yaml` 的 situation_beats 配五句模板（trigger/objective/choice/immediate/near；不配会静默套用通用模板，体检报错） |
| 一个张力引擎（整晚戏路） | `pools.yaml`「张力引擎」 | 若它属于「拿把柄换服从」那一类，把名字加进 meta.leverage_engines（禁叠规则才会覆盖它） |
| 一个压力来源（进门的由头） | `pools.yaml`「压力来源」 | 若它该自带死线，把名字加进 meta.timed_pressures |
| 一条社会规则 / 核心规则 / 美学基调 | `pools.yaml` 对应表 | 美学基调若要求写实画风，加进 meta.gate_aesthetics（写实门控随之生效） |
| 一个开场动作 | `pools.yaml`「场景动作」对应桶（交易摊牌/非交易靠近） | 建议在 `templates.yaml` 的 trade_beats / near_beats 配专属句式（不配有兜底句，体检 WARNING）；改名或删条目时同步 `templates.yaml` 的 `near_beats` 与 `suggestion_player_first` 两套键，键名逐字等于池条目名（精确匹配，不匹配则静默走兜底） |
| 一种性格反差 | `pools.yaml`「反差轴」 | 建议在 `templates.yaml` 的 contrast_line 配专属台词 |
| 一个决策轴条目（核心价值/压力策略/关系姿态） | `character_meta.yaml`「决策轴」 | 压力策略建议在 `templates.yaml` 配撤回信号与四句压力反应 |
| 一个玩家称谓 | `pools.yaml`「玩家化身轴·称谓」 | 无 |
| 一个玩家年龄段 | `pools.yaml`「玩家化身轴·年龄段」 | `character_meta.yaml`「年龄段区间」配 [最小, 最大]（不配按 28-36 兜底） |
| 一个玩家社会位置 | `pools.yaml`「玩家化身轴·社会位置」 | `identities.yaml` 的 `player` 下加身份条目；`character_meta.yaml`「社会位置关系」配关系起点 |
| 表层风味 / 口癖 / 外观条目 | `character_pools.yaml` 对应组 | 单项 ≤8 字；外观的「自然发色」「瞳色」「异色瞳」键名不可改（写实门控按名引用） |
| 一个中期转折方向 | `twists.yaml` 对应类 | 七类本身不可增删改名，类内条目随意 |
| 开局文案（处境台词、开场句式、建议动作、撤回信号……） | `templates.yaml` | 字串里的 `{npc}` 生成时替换为主 NPC 姓名 |
| 起名用字 | `names.yaml` | 无 |

表后一条硬规则：**张力引擎 / 压力来源 / 处境侧三张表不得逐字重名**（体检 ERROR）。撞名会让 near+far 事件描述同一件事且语义键不同、无法去重；分层用近义词区分（引擎=动态推到极点 / 压力=外力逼近 / 处境=当下状态，参照 `开局流程.md` §4.3）。

## 必须动代码的三类扩充（低频）

1. **新增一整条抽取轴**（比如想让开局多抽一个「天气」维度）：要改 `roll_opening.py` 的抽取计划与 `fill_opening.py` 的填装逻辑，属功能开发。
2. **裁判白名单里的枚举值**（如权力结构想加第五种、事件想加第六类）：要同步改 `validate_state.py`、`状态总结.md` 的枚举表和测试。
3. **换场许可继承的空间分类**：`commit_turn.py` 里有一张「公共/私密空间」关键词表（PUBLIC_HINTS/PRIVATE_HINTS）；新地点若用了表里没覆盖的空间词，可能需要补词，否则换场许可继承行为不符合预期。

## 有兜底、但戏味打折的地方（体检报 WARNING）

- 场景动作没配专属句式 → 用通用兜底句。
- 非交易靠近没配玩家优先建议（suggestion_player_first）→ 走 suggestion_default；改名/删条目留下的死键同样体检 WARNING。
- 压力策略没配撤回信号/压力反应 → 用通用撤回、按「正面解决」兜底。
- 反差轴没配专属台词 → 用通用句。
- 身份族没配权重 → 按 8 计。
- 社会位置没配关系起点 → 按陌生直连兜底；年龄段没配区间 → 按 28-36 兜底。

唯一没有兜底、会**静默降级**的是处境模板：池子里有处境而 `templates.yaml` 没配模板时，开局不报错，直接套用「今夜话没说完」的万能模板——所以体检把它报为 ERROR。

## 维护自查一句话

改完任何内容：`python scripts/check_content.py && python -m pytest tests -q`，全绿收工。
