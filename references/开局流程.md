# 开局流程

本文件只负责开局：1-14 流程表、随机性与多样性协议、seed 映射规则、素材使用规则与单次开局校验。人物字段以 `references/角色设计.md` 为准，时间、事件与追算以 `references/世界运转.md` 为准，落档与保存检查以 `references/状态总结.md` 为准，命令与运行时事务以 `SKILL.md` 为准。

开局提交点即回合 1，首段正文显示「回合：1」。开局过程（骰子、角色卡、候选与评分、压力种子、校验过程）全部在后台执行，不向玩家展示。`meta.turn` 是唯一回合号，存档与显示一致。

## 随机性与多样性协议

1. 结构骰优先运行 `python scripts/roll_opening.py` 一次性取全部结构骰；脚本不可用时，按本文件固定顺序手工抽取，但不得声称获得脚本的 `protocol_version` 或历史签名。
2. 默认模式为脚本的 `table`；`--all-custom` 才进入 `all_custom`，此模式只允许脚本 `CUSTOM_KEYS` 中的核心规则、张力引擎、时代、地点、社会规则、压力来源、场景动作、身份族、处境和人物决策轴通过 `--custom KEY=VALUE` 自拟，其余轴仍由脚本抽取。`--custom` 不得脱离 `--all-custom` 使用。
3. `--force-table` 进入 `force_table`；与 `--all-custom` 互斥，禁止 `--custom`，所有锁定值必须来自解析后的表内池。
4. `预锁 X=Y` 对应可重复使用的 `--lock X=Y`；锁字段只能来自脚本 `LOCKABLE_KEYS`，同一字段不可重复 lock，表内模式的值必须存在于对应解析池。张力引擎是多值字段：`A` 表示锁定其中一项、另一项自动从池中补抽且互不相同；`A、B` 表示锁定两项（顿号或逗号分隔），两项不得重复；超过两项或含重复项会被脚本拒绝。
5. `种子 N / seed=N` 对应 `--seed N`；N 必须是非负整数。未提供时脚本使用系统熵生成 0..2^31-1 的 seed，并在输出首行显示实际 seed；协议版本固定记录为 `opening-roll/v3`。
6. 连续开局的差异性由脚本近期历史签名与「时代×地点×张力引擎」三元组共同辅助：默认将结果写入临时目录的 `adult_tension_narrative_roll_history.jsonl`；重复签名或重复三元组只发 warning，不阻断开局。`--no-history` 跳过读取/写入历史，仅用于维护自检或明确要求不留历史。
7. 防塌缩（表内模式、字段未被预锁时）：不得把「债务压力、秘密暴露倒计时、第三方施压」两项叠在同一局；`player_high` 不得默认给主 NPC 配「债务压身 / 秘密将破 / 时限临门」；场景动作默认抽「非交易靠近」；身份族按权重降低权力/商业、提高医疗/手艺/家族/艺术；玩家化身抽称谓、年龄段、社会位置，禁止默认「先生 + 精英男 + 制度杠杆」。
8. 自然语言开局约束（如「开局：当代，两个人对等，不要职场」）由执行层映射为 `--lock`，字段和值仍须符合 lock 规则。
9. `--format json` 只改变输出格式；`--twist` 改为抽取 2-3 个转折方向并退出，不生成完整结构骰。第一次跨天且 `meta.simulation` 为 true 时才掷一次，经事件队列落地。
10. 结构骰只服务后台生成；正文不得出现骰子、字段名、Tier 或校验过程。

## seed 映射规则

1. `种子 N / seed=N`：N 为非负整数，对应 `--seed N`，记入 `opening_request.seed`。
2. 映射：脚本以 `random.Random(N)` 初始化，按 `DRAW_PLAN` 的固定顺序消费随机数；同一 seed、同一 `opening-roll/v3`、同一版本素材表与脚本产生相同结果。
3. 未提供 seed：脚本从系统熵生成 0..2^31-1 的 seed，实际使用的值出现在输出首行并记入 `opening_request.seed`。
4. 手工抽取：按 `DRAW_PLAN` 的固定顺序执行，但不得伪造脚本的随机映射、协议版本或近期历史结果。
5. `opening_request` 是后台开局过程记录，至少含 `seed`、`protocol_version`、`mode`、locks、custom、history 使用状态与校验结果；不进台账、不进存档。

## 素材使用规则

1. `setting_shell` 四字段来源：`type` 与 `place` 来自「时代与地点」表（步骤 2），`rule` 来自「社会规则」表（步骤 3），`pressure` 来自「压力来源」表（步骤 4）。
2. 四项必须为非空字符串且始终是四字段映射；「表外全随机」允许对应字段自拟，仍不接受一句话字符串。
3. 身份族、处境、反差轴、决策三轴、表层风味、口癖、外观轴与玩家化身轴的池及语义分别以 `references/素材库.md` 与 `references/角色设计.md` 为准。场景动作分「交易摊牌」「非交易靠近」两桶，未决动作默认取后者。

## 开局编排

运行环境能执行脚本时，按以下流程编排开局（不能执行脚本时按「随机性与多样性协议」手工抽取，并保持同一产物结构）：

1. `python scripts/roll_opening.py [--seed N] [--lock KEY=VALUE]... [--all-custom] [--force-table]` 取全部结构骰。
2. `python scripts/build_opening.py [--seed N] [--lock KEY=VALUE]... [--out <路径>]` 生成 v3 骨架：结构字段、ID、时钟、事件与 checkpoint 已就位，内容字段为空。未指定 `--out` 时默认写入 `saves/_opening_<seed>.yaml`；同一路径已存在时拒绝覆盖（换 seed 或另指定 `--out`）。可用 `--roll-file roll.json` 复用 `roll_opening.py --format json` 的输出（校验协议版本与 seed）。
3. 按「1-14 开局流程」把内容字段填实（起名、年龄、身份、处境、决策卡、双语态、亲密画像、关系边、事件语义、当前节点等）。`--all-custom` 模式下未自拟的核心轴在骨架中为 `custom_required` 占位，必须在此阶段替换为真实值。
4. `python scripts/build_opening.py --check <文件>` 反复运行：输出即待填/待修字段清单，全部消除（exit 0）前不得进入正文。
5. 校验通过后按 `SKILL.md`「完整开局」输出正文（允许三行进度，然后一次性输出世界观/故事/正文/【此刻】/回合 1），并把 seed、协议版本、模式、锁、校验结果记入后台 `opening_request`（可在生成骨架时用 `--request <路径>` 顺带产出）。`unresolved_action` 必须落在非交易靠近，除非玩家预锁了交易摊牌。配角未进场时不要生成完整配角卡。

`build_opening.py` 不写 roll 历史签名，避免污染近期去重辅助；骨架的 `attraction.orientation` 为唯一表末自拟位，由模型按角色背景自拟。

## 1-14 开局流程

14 个步骤不得跳步或合并；每步产出在后台状态中可查，单次开局校验未通过不得进入正文。

| 步骤 | 名称 | 规则 | 产出 |
|---|---|---|---|
| 1 | 世界壳与核心规则 | 抽核心规则、美学基调、权力结构；抽 2 项互不相同的张力引擎 | `meta.power_structure`、`world.tension_engines`、核心规则与美学基调进入 `world.constants` |
| 2 | 时代与地点 | 抽时代、地点 | `setting_shell.type`、`setting_shell.place` |
| 3 | 社会规则与世界常量 | 抽社会规则；把步骤 1-3 抽中的规则类项写成世界常量（至少 1 项） | `setting_shell.rule`、`world.constants` |
| 4 | 压力来源与三层压力种子 | 抽压力来源；建立 immediate 现状压力、near 事件与 far 钩子事件 | `setting_shell.pressure`、`world.pressure_seeds`、事件占位 |
| 5 | 玩家化身 | 预锁姓名只做合规与去重；未预锁按 `references/角色设计.md` 标准起名；生成化身卡与初始硬边界 | `player` 全部字段、`boundaries` |
| 6 | 主 NPC 标准起名 | 完成 9a 的起名：`name_profile`、≥3 候选、排除、选定、`naming_audit`；checks 任一 fail 即不合格。姓名审计与最终姓名必须同时写入该 NPC，不得只在开局过程留候选 | `naming_audit`、姓名字段 |
| 7 | 主 NPC 年龄与身份 | 年龄≥18 且明确；按身份族补具体身份、公开名声与身份档；身份档必须能解释资源、限制和风险 | `age`、`identity`、`identity_profile`、公开名声 |
| 8 | 主 NPC 处境档 | 按处境类型补齐触发、压力、目标、期限、未决选择、信息差、退出通道、后果与局势句；处境不得推导服从或许可 | `situation` |
| 9 | 主 NPC 全维角色卡 | 完成 9c-9g：决策三轴与可选反差轴、亲密画像核心子集、对玩家初始关系值与原因、语言滤镜与双语态、生成清单八项、`decision_card` 与自主冷却初始值。所有关系值只落在步骤 14 的顶层关系图 | main NPC 其余字段、`autonomy` |
| 10 | 开场三勾与事件队列 | 把步骤 4 的三层压力落成事件：immediate、near、far（far 必 `hook: true`）；每项均带稳定 ID、唯一 `semantic_key`、非空 `source` 和可恢复的 `due_at`（无固定时间则为 null） | `events` |
| 11 | 当前节点与未决动作 | `location`、`participants`、`situation`、`last_committed_result`、`unresolved_action`（停在玩家可接手处；可抽「场景动作」作未决动作类型）、`natural_next_pressure`；`location` 必须与当前场景一致 | `current_node` |
| 12 | 场景许可与退出通道 | 新建与 `current_node.location` 绑定的 `scene_id`、`grants` 为空；确认 `safety_state: running`、`exits` 可用。后续任何地点、场景或参与者变化均须更换 `scene_id` 并重置当前场景许可 | `consent`、`exits` |
| 13 | 配角 | 功能确认 → 配角简起名 → 核心价值与压力策略 → 其余字段（`references/角色设计.md`「配角」）；实际进入亲密线前先升为 `important_supporting` 并补齐规定字段 | `npcs[supporting…]` |
| 14 | 顶层关系图落档 | 为 player↔各 NPC 建边；多名 main 之间的关系一并生成；9e 初始关系值与原因以顶层边的 `trust`、`type`、`channel` 及相关人物记忆共同表达，不在人物卡覆写 | `relationships` |

步骤 9 的 9a-9g 子步与 9g 生成清单以 `references/角色设计.md`「主 NPC 全维角色卡」为唯一来源；步骤 5、13 的起名要求分别以 `references/角色设计.md`「玩家化身」「配角」为准。

## 单次开局校验

1-14 全部完成后、进入正文前，逐项核对完成度清单；任一失败即 `validation.passed: false`，不得进入正文。任何条件项不适用时显式写「—」及原因。

| 编号 | 检查项 | 通过标准 |
|---|---|---|
| C1 | 世界壳 | `setting_shell` 四项均为非空字符串 |
| C2 | 常量与引擎 | `world.constants` 与 `world.tension_engines` 均非空 |
| C3 | 压力种子 | `pressure_seeds` 齐全；near/far 引用存在且 kind 匹配；`far_event_id` 指向唯一 far 事件，far 为 hook |
| C4 | 玩家化身 | 年龄≥18 且明确；姓名、身份、基线、名声非空；资源与知识可用 |
| C5 | 主 NPC 起名 | `naming_audit.checks` 全部 pass；候选≥3、`chosen` 非空，且 chosen 与正式姓名字段一致 |
| C6 | 主 NPC 身份 | 年龄≥18 且明确；`identity_profile` 字段补齐 |
| C7 | 处境档 | 字段齐全、局势句成立 |
| C8 | 9c-9g | 三轴、可选反差轴、亲密画像核心子集、双语态、决策卡、9g 八项与自主冷却初始值齐全 |
| C9 | 开场三勾 | immediate/near/far 事件齐全，hook 语义正确；每个事件有唯一 ID/`semantic_key`、非空 `source` 与合规 `due_at` |
| C10 | 当前节点 | 字段齐全；`unresolved_action` 停在玩家可接手处；`current_node.location` 与当前场景地点一致 |
| C11 | 场景许可 | `scene_id` 非空并绑定当前地点；`grants` 为空或仅 granted 且参与者⊆当前场景 |
| C12 | 配角 | 每名配角功能、简审计合格、必存字段齐全；已入亲密线者均已升级为 `important_supporting`；缺合格简审计即步骤 13 未完成 |
| C13 | 关系图 | player↔各 NPC 有边；多名 main 之间已生成；人物卡不存在覆盖顶层 `relationships` 的关系数值 |
| C14 | 安全项 | 全部角色年龄≥18 且明确；无 active 边界被场景违反；`safety_state: running` |
| C15 | 开局校准 | 已触发并完成一次深度校准；`last_full_turn: 1`、`next_full_turn: 6`，最终可恢复状态的 `force_full: false`、`force_reason: null` |

校验通过后把 `validation.passed: true` 记入后台 `opening_request`，再按 `SKILL.md`「完整开局」输出【世界观背景】【故事背景】【正文】【此刻】与「回合：1」。新局不得写入 `directives`。
