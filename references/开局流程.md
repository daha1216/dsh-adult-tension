# 完整开局流程

本文件规定开局的执行顺序、随机性协议、素材使用规则、校验与落档。抽样表见 `references/素材库.md`（脚本骰成功时无需读取）；角色卡结构、起名、身份档与处境档见 `references/角色设计.md`；玩家可见输出与安全不变量以 `SKILL.md` 为准。

## 完整开局规则

执行新开局时完整运行 1-14，随后生成玩家化身、三层压力种子和开场三勾。表格是抽样种子，不是合法全集；允许根据已生成身份做小幅改写，但不得二次挑选结果。

默认采用“表结构末位自拟”：每个结构表在表内选项之外增加一个“系统自拟”末位。玩家说“强制表内”时取消末位；玩家说“表外全随机”时仍执行全部步骤，核心规则、引擎、壳、动作、身份、处境和人物决策轴自拟，其他轴照常抽取。

角色年龄与成年教育表述按 `references/角色设计.md` 执行；开局安全校验按 `SKILL.md` 不变量执行。

### 模块边界

各模块只负责自己的问题；同一事实只在一个模块中设为正式字段，其他模块只能引用，不重复改写（例如身份侧保存“权限来源”，处境侧只描述该权限此刻是否够用）：

```text
世界观档、核心规则与基调轴：决定哪些素材可用、什么规则改变日常，以及本局质感。
张力引擎：说明什么矛盾正在变贵。
制度与场合壳：提供一个地点、一条规则和一项压力。
开场动作：说明人物此刻正在共同做什么，并提供未完成动作。
身份侧：解释角色凭什么拥有资源，以及受到什么限制。
处境侧：说明角色为什么现在必须行动。
人物生成：生成身体、人格、亲密画像和决策规则。
因果网络：把角色选择转化为关系、事件和后果。
```

## 随机性与多样性协议

语言模型没有真随机，默认会挑“最顺手”的表项，导致同一题材下开局趋同。结构骰分两类，全部按本协议执行：

- **表骰**：从素材表抽行的骰——世界基调与核心规则各轴、季节与时景各轴、大类细分各轴、引擎族与族内项、壳类、开场动作、身份族与身份种子、处境类型、人物决策轴、关系阶段、反差轴、配角功能、表层风味、口癖。
- **范围骰**：小范围整数骰——世界观档 1..3、咬合 1..2、Tier 1..3、模式 1..2、权力结构 1..4、配角数 1..3。

1. **脚本骰优先**：运行环境能执行脚本时，先运行 `python scripts/roll_opening.py`（可加 `--seed N`、`--genre 大类`、`--lock 字段=值`、`--no-custom`、`--all-custom`、`--no-history`、`--mains N`、`--twist`；仅查题材时用 `--list-genres`），直接采用其输出作为全部结构骰结果，跳过第 2、3 条的手工抽取，且无需读取 `素材库.md`；仅当某项与预锁或已生成内容明显不成立时，自拟一个同类替代或重跑一次脚本。在 `validation.checklist.notes` 记录 `dice_source: script`。脚本不可用或报错时退回手工抽取并加载 `素材库.md`，记录 `dice_source: protocol`。
2. **表骰先枚举后选择（手工时）**：每个表骰先在内部列出 min(5, 表长) 个候选，候选尽量来自 3 个不同族/行；再从中选择与已锁定要素咬合最紧、且最近可见对局未用过的一项。禁止直接取表格首行、该题材最著名的选项，或每次都挑同一“最有趣”的选项。
3. **范围骰不取惯性值（手工时）**：在合法范围内自由取值，禁止总是取中间值、默认值或与上一局相同的值。
4. **范围只锁大类**：玩家限定题材范围（如“末世”“修真”）时，只锁定大类；`素材库.md`「大类细分轴」中的各轴仍须逐轴重新抽取。禁止把该题材的刻板组合（如 末世＝丧尸＋避难所＋压抑求生）当默认结果。
5. **跨局覆盖感知**：脚本把世界档、核心规则、题材、引擎、壳、动作、身份、处境、关系阶段和人物决策轴写入根目录 `.opening_history`（运行态，不入库），只保留最近 30 条；无 `--seed` 时比较 16 个候选，优先选择单项和关键配对较少重复者，并硬避最近 5 局的“引擎族×壳类×身份族”原组合。旧三项历史可直接读取。`--seed N` 跳过历史以保证复现；`--no-history` 关闭历史读写。手工抽取时同样优先使用近期少见的单项和配对。
6. **seed 映射（手工后备）**：脚本可用时，“种子 N”直接作为 `--seed N` 传入脚本。手工时对第 k 个结构骰取表内第 `(N + k) mod 表长` 行（k 按 1-14 步骤序号计，同一步骤内多个轴按轴序顺延；行号从 0 起）。命中预锁项、明显不成立项或不适用的“系统自拟”末位时，向下顺延一行。seed 只约束结构骰，不约束文本细节。
7. **锁定项除外**：预锁字段和玩家边界不参与本协议，也不得以“换个更有趣的”为由被改写。

手工抽取表骰前必须已实际读取 `references/素材库.md` 的对应表（表层风味、配角功能与画像倾向表在 `references/角色设计.md`）；不得凭记忆虚构表项。协议执行过程全部留在后台，不向玩家展示候选、理由或映射计算。

## 素材使用规则

本节规定抽出的结构骰结果如何落成正式字段；身份与处境的落档结构见 `references/角色设计.md`「身份档」「处境档」。

### 世界观档

世界观档决定世界规则，Tier 只决定追算深度。先确定世界观档，再按下列规则加载各表内的增补；具体素材只在 `素材库.md` 对应表中维护。

| 档位 | 基础规则 |
|---|---|
| 现实 | 资源、身份、身体和制度遵循现实逻辑 |
| 半架空 | 保留现实社会，只加入一层异常规则、能力或特殊机构；使用通用池 + 各表的半架空增补 |
| 强架空 | 世界法则、种族、契约、力量和社会制度均可不同；使用通用池 + 各表的强架空增补 |

现实档不得加载增补；半架空与强架空增补不得混用。通用池不得放入需要异常、异界、系统或超自然前提的素材，这类素材只放在对应增补中；预锁项与世界观档冲突时停止开局。增补只改变世界规则和可用素材，不改变角色年龄、玩家控制权或当前场景许可。强架空中的契约、血统、命运和阶位不能自动替代角色的拒绝或同意。

### 世界基调卡

步骤 1 在确定档位后，逐轴抽取生成世界基调卡。每轴独立抽取，允许并鼓励反差组合（如 末世×温柔日常、宫廷×黑色幽默）；基调卡写入草稿，落档时作为 `world.constants` 的来源之一。玩家限定题材时加抽「大类细分轴」；未收录的大类比照该节自拟细分轴后逐轴抽取。

美学基调只影响画面质感、比喻系统、对白口吻和表层风味的可用池，不改变安全不变量、许可判定或 `SKILL.md` 的性行为场景写法标准。玩家点名时预锁该风格；未指定时与其他世界基调轴一样随机抽取。

```yaml
world_tone:
  era_tech: null
  region: null
  society: null
  narrative_tone: null
  aesthetic: null
```

### 世界核心规则

逐轴抽取“核心规则来源、掌握范围、生效代价、变化阶段”。先依据题材把来源具体化为可观察、可违反的规则，不得直接把类别名当设定；再合成为一句可验证的世界常量：

```text
在本世界，<具体规则>；其可用性或约束范围是 <掌握范围>，使用或违背它会付出 <代价>；
当前正处于 <变化阶段>，这使开场压力成立。
```

现实档只用通用池；半架空和强架空只加载各自增补。结果写入现有 `world.constants`，不新增存档字段。大类题材先按兼容标签限制世界观档，再对具体细分项执行现实档排除。

### 开场时景

随步骤 1 抽取 `素材库.md`「季节与时景轴」各轴，作为开场氛围与感官细节建议，融入【世界观背景】与【正文】，不单独输出，不写入存档结构。与世界设定明显不合时（如星际、异界），换用该世界的等价时景。

### 张力引擎

先选择 9 个核心族之一，再选择族内具体项。核心族只定义冲突来源，具体项负责把冲突落成可演事件。将结果翻译成“谁拥有什么、谁缺什么、什么即将改变”的一句压力，不要只输出标签。

双引擎必须形成因果连接，禁止把两个标签简单并列：

```text
因为 <主引擎压力>，所以 <副引擎> 变得更昂贵或更危险。
```

### 制度与场合壳

从壳表选择一种壳（壳＝提供场所、规则与压力的外框），再只补全一个具体地点、一条当前规则和一项压力。壳表只收场所类型；交易、契约、展演等机制由张力引擎和处境负责，不得反过来充当地点。表格是灵感池，不要求把制度细节展开成复杂设定。

正式结果固定为：

```yaml
setting_shell:
  type: null
  place: null
  rule: null
  pressure: null
```

```text
<场合类型>中的<具体地点>；
当前规则是<限制>，它让<人物/玩家>必须在<压力>下做选择。
```

`rule` 只写当前最有效的一条限制，例如“非董事不得接触原始文件”或“十点后客区封闭”。`pressure` 必须说明它如何让至少一个开场选择更难或更贵；无关剧情的监控、权限、出口或条款不生成。

壳只提供制度、场合和压力；角色态度与当前许可按 `SKILL.md` 判定。

### 开场动作

从动作母型选择“动作族→具体种子”，与壳、处境分别回答“在做什么、在哪里做、为什么必须现在做”。把具体动作写入 `situation.trigger` 或 `immediate_objective`，把尚未完成部分写入 `current_node.unresolved_action`；不新增正式字段。动作与壳明显不合时，只把动作换成同族等价行为，不重抽世界。

## 开局事务流程

凡 1-14 各步要求“建立稳定 ID”或“提交初始状态”，均延后到原子落档阶段执行；落档前只保留无正式 ID 的草稿。

### 五阶段流程

| 阶段 | 行为 | 写入正式状态 |
|---|---|---|
| 1. 读取要求 | 固化模式、预锁项、边界与种子 | 否 |
| 2. 生成草稿 | 完成 1-14 及附加内容 | 否 |
| 3. 开局校验 | 核对完成度清单，检查结构、因果、人物、安全、名字与重复度 | 否 |
| 4. 局部修复 | 仅修错误字段，最多两轮；每轮后重新校验 | 否 |
| 5. 原子落档 | 一次性生成 ID、提交状态并渲染开场 | 是 |

### 1. 读取要求

```yaml
opening_request:
  mode: default
  locks:
    world_type: null
    setting_shell: null
    scene_action: null
    npc_identity: null
  player_boundaries: []
  seed: null   # 玩家提供“种子 N”时记入；映射规则见「随机性与多样性协议」
```

将玩家明确指定的任意字段加入 `locks`。预锁字段在本次开局中不可改写；若组合困难，只能调整未锁字段。边界同样不可作为修复目标。

### 2. 生成草稿

按步骤 1-14 依序生成，再生成玩家化身、三层压力种子、开场三勾与当前节点；各步起名时机与流程以 1-14 表和 `references/角色设计.md`「名字生成与去重」为准。所有结果仅写入：

```yaml
opening_draft:
  world: {}
  player: {}
  npcs: []
  relationships: []
  events: []
  current_node: {}
  validation: {}
```

草稿期不得生成正式角色或事件 ID，不得推进时钟或回合，不得写入正式台账。草稿内如需互相引用，使用仅在草稿有效的临时键。`opening_draft` 不是 v3 存档，不得直接交给 `scripts/validate_state.py` 或用于载入。

### 3. 开局校验

开局进入一次校验流程（不再另跑独立的「全跑核对」）。初检后若有错误，进入局部修复；每轮修复后重新执行本节校验，最多两轮。

校验第一步是逐项核对完成度清单，任何一项缺失、为空或既非 `done` 也非 `n_a`，一律 `passed: false`；`n_a` 只允许出现在条件步骤（4 副引擎、14 关系图），且必须在 `notes` 附原因：

```yaml
validation:
  checklist:
    s1_world_tone: done      # 世界观档 + 世界基调卡 + 世界核心规则
    s2_engine: done
    s3_mesh: done
    s4_sub_engine: done|n_a
    s5_shell: done           # 壳 + 开场动作
    s6_tier: done
    s7_mode: done
    s8_power: done
    s9_main_npc: done        # 含 9a-9g 与合格 naming_audit
    s10_relation_stage: done
    s11_cast_count: done
    s12_cast_roles: done
    s13_cast_cards: done     # 每名配角含合格简 naming_audit
    s14_relation_graph: done|n_a
    player_avatar: done
    pressure_seeds: done
    opening_hooks: done
    notes: []
  passed: false
  errors:
    - field: npcs[0].resources
      reason: 身份无法支持最高权限
      repair: 降低权限或为未锁字段补充合法来源
```

清单通过后，再按以下层次检查完整草稿：

- 结构：1-14 是否完成；字段、人数、功能、关系边一致。
- 因果：核心规则能解释世界压力；身份能解释资源与权限；远近事件有压力来源。
- 人物：决策轴已落实为目标、底线或行为，且知识、资源、压力反应兼容。
- 亲密：开局核心画像独立生成、无刻板绑定；未自动扩大许可。
- 安全：按 `SKILL.md` 不变量校验。
- 名字：主 NPC/未预锁玩家为标准审计；配角为简审计；同局不重名、读音不冲突；配角更普通。
- 重复度与协议：身份组合、处境和标志细节不过度重复；玩家限定题材时，产出不得等于该题材的刻板模板（如 末世＝丧尸＋避难所＋压抑求生）；结构骰须符合「随机性与多样性协议」；禁止按「更有故事感」翻案未选中候选。

每条错误定位到字段，并给出不触碰预锁项和玩家边界的修复方式。无错误时 `passed: true` 且 `errors: []`。此处 `validation` 只用于开局草稿校验；存档结构错误由 `scripts/validate_state.py` 输出，两者不是同一错误格式。

### 4. 局部修复

每轮只修改 `validation.errors` 指向的字段及其直接依赖，禁止因局部问题重抽整个世界。修复顺序：

1. 年龄、边界和玩家控制权。
2. 世界与身份冲突。
3. 目标、资源和事件冲突。
4. 人物知识越界。
5. 亲密画像绑定错误。
6. 名字：主 NPC 缺标准审计 / 配角缺简审计 / 重名读音 / 配角不够普通。
7. 文风、细节重复和刻板模板。

名字错误只允许重跑该角色起名或替换未锁姓名，不得借机重抽世界或亲密画像。预锁姓名只做合规与去重，不得改写。

每轮修复后重新执行开局校验，最多两轮。两轮后仍失败则终止开局，不得渲染正文或提交草稿。

### 5. 原子落档

仅当 `validation.passed: true` 时一次性完成：生成稳定 ID、写入世界常量（含世界基调卡来源）、决策卡、合格 `naming_audit`、关系边、三层压力事件和当前节点，提交为回合 0；再按 `SKILL.md` 开局输出格式渲染（回合：1）。

落档是单次事务：任一字段、引用、起名审计或 ID 失败则整体回滚。无合格起名审计不得落档。落档与渲染均不向玩家展示骰子、角色卡、起名候选/评分、`naming_audit`、压力种子、校验清单或内部台账；仅当玩家明确要求“存档”时，按 `references/状态总结.md` 输出可恢复 YAML。

## 1-14 开局流程

| 序 | 项目 | 规则 | 产出 |
|---|---|---|---|
| 1 | 世界观档、基调与核心规则 | 档位 1..3；逐轴抽取基调和世界核心规则；限定题材时先应用兼容档位，再加抽大类细分轴 | 档位 + 基调卡 + 一句世界常量 |
| 2 | 主张力引擎 | 9 个核心族之一与族内具体项（`素材库.md`「张力引擎」） | 一句可演压力 |
| 3 | 咬合开关（两引擎是否联动） | 1..2 | 单引擎 / 双引擎 |
| 4 | 副引擎（对冲） | 仅双引擎时生成，族不得与主引擎相同 | 第二条压力 |
| 5 | 制度与场合壳、开场动作 | 分别抽壳类和动作族；壳给地点/规则/压力，动作给正在进行和尚未完成的行为 | 壳结构 + 动作种子 |
| 6 | Tier | 1..3 | 世界追算深度 |
| 7 | 模式 | 1..2 | reliable / immersive |
| 8 | 权力结构 | 1..4 | 玩家高位 / NPC高位 / 对等 / 可切换 |
