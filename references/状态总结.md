# 状态总结与恢复

## 职责与原则

存档必须让一个新实例直接重建当前状态，而不是重放历史。载入时不得重新执行开局、重新抽取角色、重掷随机结果或改变已提交结果。

命令语义、玩家可见输出、回合事务和安全不变量以 `SKILL.md` 为准；时间、Tier 追算、事件处理和历史压缩以 `references/世界运转.md` 为准；角色字段以 `references/角色设计.md` 为准。本文件只规定 v3 存档结构、持久化语义、保存检查和恢复流程。

机器可验证的结构、类型、枚举、引用和时序约束，以 `scripts/validate_state.py` 的执行结果为唯一准则；本文件不复制一套平行的机器 schema。校验器使用两种 profile：`save` 用于已有存档的完整恢复校验，`opening` 用于回合 1 开局提交；两者共享同一核心结构和引用约束，`opening` 额外要求开局三勾、命名审计、步骤 6-9 产物及首次深度校准。

## 存档槽与冲突检测

v3 YAML 是叙事状态本体，不包含会话锁。`saves/current_state.yaml` 是本会话工作活档。持久化层使用以下布局：

```text
saves/
  slots/
    <slot>/
      state.yaml       # save_version: 3，继续用 save profile 校验
      manifest.yaml    # manifest_version、slot、created_at、updated_at
      .write.lock      # 仅供 manage_saves.py 使用的进程锁
```

`scripts/manage_saves.py` 是命名存档的初始化、列出、载入与原子写入实现入口。每个会话默认绑定自己的存档；载入时记录 `manifest.updated_at`，保存时必须携带载入时观察到的 `updated_at`（缺省该参数会被直接拒绝，不再静默放行）。槽位已被其他窗口写入（`updated_at` 不一致）时拒绝覆盖，不自动合并两个窗口的状态；需要保留两种走向时，把当前版本另存为其他名称。`.write.lock` 只保护存储提交，不增加回合，也不改变叙事状态字段。

以下信息不可压缩：

- 角色稳定 ID、姓名和已确认年龄
- 世界常量、张力引擎、当前壳与压力种子
- 当前安全状态、玩家硬边界和可恢复的场景接续点；当前互动判断不作为同意记录持久化
- 当前模式、Tier、`simulation`、回合号和世界时钟
- NPC 核心字段、近期记忆和自主冷却
- 顶层关系图中仍会影响传播或决策的关系边
- 未兑现的跨回合承诺、pending 事件和远程钩子
- 最近一次完整 checkpoint
- `current_node` 的可恢复接续点

## 当前运行状态

### 字段职责与唯一来源

状态读取按以下职责分层，避免把同一事实从多个字段拼接或互相覆盖：

- `current_node.situation` 是当前场景处境的唯一正式来源，负责此刻的触发、压力、目标、信息差、退出通道和后果。
- `npcs[].situation` 是 NPC 的长期背景处境，负责角色为什么处于当前生活状态；它不覆盖 `current_node.situation`。
- `relationships` 是关系数值与关系边的唯一来源；角色卡和 `decision_card` 不保存关系数值副本。
- `events` 保存仍可能影响未来的事件；`resolved_summary` 只保存已经稳定的历史结果。
- `checkpoint` 只表示最近一次完整校准及本回合变化摘要，不是完整历史台账。
- `current_node.unresolved_action` 是玩家接手点；它不等于 NPC 已经做出的关键决定，也不替玩家完成选择。

普通回合优先读取 `references/运行状态速览.md` 规定的活切片；只有遇到换场、重大事件、跨天、恢复失败或需要深度校准时，才回到本文件和完整存档。

### 字段枚举速查

以下枚举与 `scripts/validate_state.py` 的常量对应；新增或修改取值时必须同步脚本、文档和测试。

| 字段 | 合法取值 |
|---|---|
| `meta.mode` | `reliable` / `immersive` |
| `meta.tier` | `1` / `2` / `3` |
| `meta.power_structure` | `player_high` / `npc_high` / `equal` / `switchable` |
| `boundaries[].status` | `active` / `revoked` |
| `meta.safety_state` | `running` / `paused` |
| `events[].kind` | `immediate` / `near` / `far` / `timed` / `probabilistic` |
| `events[].status` | `pending` / `resolved` / `cancelled` |
| `npcs[].role_level` | `main` / `important_supporting` / `supporting` |
| `relationships[].trust` | 整数 `-5` 到 `5` |
| `npcs[].intimacy.scope` | `none` / `non_intimate` / `intimate`（intimate 须先升级角色） |

`meta.mode` 与 `meta.tier` 当前版本为保留字段：校验器只做枚举检查，脚本对两者没有任何分支逻辑，不改变任何行为；开局骨架固定写 `mode: reliable`、`tier: 1`。

NPC 的 `sexuality_development.plasticity`、`trend` 及各个 main 专属对象的内部结构，以 `references/角色设计.md` 为准；本文件只要求这些对象在需要时持久化。

## 事件与未兑现承诺

同一 `semantic_key` 不得对应多个事件；`pending` 事件必须携带非空 `semantic_key`，已解决或已取消事件可在压缩前省略。已解决/已取消事件保留在 `events` 列表中；`resolved_summary` 是其摘要镜像，折叠条目的 `event_id` 沿用原事件 ID、`resolved_turn` 记折叠发生回合、概括句放 `outcome`。

事件进入运行上下文的层级如下：

- `pending`：进入普通回合活切片，按到期时间、创建回合和稳定 ID 排序；它们仍可能改变当前决策或未来压力。
- `resolved` / `cancelled`：不进入普通回合的行动上下文，只在历史压缩、恢复检查或深度校准时读取。
- `checked_turns`：只用于判断某回合是否已经检查过且未命中，不应当被当作待处理事件。

未兑现的承诺必须保留稳定 ID、触发条件、未兑现原因和实际后果；不能用一句“以后处理”代替 pending 事件。

### 当前互动判断

当前互动判断不持久化为 `consent` 或 `grants` 结构。模型根据当前参与者、地点、行为、NPC 明确反应、撤回信号、玩家硬边界、NPC 长期底线、年龄校验和 `meta.safety_state` 判断下一步是否可以继续。明确撤回立即生效；含混、沉默或压力不视为同意。

换场只更新 `current_node.scene_id`、`location` 和 `participants`；不继承旧场景的互动判断，新场景重新依据当前信号判断。

### 可选扩展字段

以下字段只服务叙事，有值才保存，缺失时按默认值处理。除表中注明外，它们不属于 v3 核心 schema，`validate_state.py` 不校验其取值；`npcs[].intimacy` 与 `relationships[].opening` 属**受校验**的结构字段，约束见上方模板注释与枚举速查。

| 字段 | 位置 | 取值 | 缺失默认 |
|---|---|---|---|
| `active_voice_mode` | 每个 NPC | `surface` / `inner` | `surface` |
| `voyeur_pov` | `meta` | `on` / `off` | `off` |
| `event_seed` | `meta` | 稳定随机种子 | `0` |
| `scene_profile` | `current_node` | 地点行为画像映射 | 缺失时按地点基础信息处理 |
| `action_category` | `current_node` | 非交易动作分类名 | 缺失时按 `unresolved_action` 处理 |
| `action_metadata` | `current_node` | 动作功能、可见度和升级度映射 | `{}` |
| `identity_profile.behavior` | 每个 NPC 的身份档 | 身份族行为画像映射 | `{}` |
| `function` | 每个 NPC | 非空字符串 | 无（角色功能不明确时不写） |
| `appellation` | `player` | 非空字符串 | 按姓名与身份自然称呼 |
| `checked_turns` | `events[]` | 已判定未命中的玩家回合列表 | 无（未判定过不写） |
| `last_roll` | `events[]` | `{turn, value, outcome}` 概率判定记录 | 无（未抽取过不写） |
| `twist_state` | `world` | `{generated_count, last_generated_turn, last_reason}` | 无（未生成转折时不写） |

`active_voice_mode` 载入后保持存档中的状态，不重新判定，也不因载入自动退回表层。`voyeur_pov` 经 `commit_turn` patch 落盘，只影响叙述层能否展现 NPC 未表露的内心，不改变任何角色的信息集。
`event_seed` 只参与概率事件的稳定抽取，不改变开局骰或其他随机流程；缺失时按 `0` 处理。

## checkpoint 与恢复

### 时间与 checkpoint

- `clock`、`previous_clock` 和事件 `due_at` 使用**带时区偏移**的 ISO 8601 字符串；不带偏移的本地时间不具备可恢复性。
- `delta_t` 是 `clock - previous_clock` 的非负整数秒；`delta_human` 仅供人读，可为空，不参与计算。
- 开局或无时间流逝时，`clock == previous_clock` 且 `delta_t == 0`。开局之后的普通行动默认推进 1–15 分钟（`delta_t` 即 60–900 秒）；「继续」必须让时钟变化。
- 有时间变化时，先把旧 `clock` 写入 `previous_clock`，再写新 `clock` 与对应 `delta_t`。
- `checkpoint.changed` 记录本回合重要变化的字段路径和原因，不是完整台账。
- pending 事件的 `due_at` 必须晚于 `world.clock`（机器校验）；到期即被 `commit_turn.py` 自动标为 resolved，种子引用随之重指或置空。
- 提交器强制「推进中的回合必须让时钟前进」；零推进只允许出现在开局或 `advance_turn: false` 的元指令提交。旧档中的连续零推进属历史遗留，载入后按正常规则推进。
- `last_full_turn` 不得大于当前回合；`next_full_turn` 始终为 `last_full_turn + 5`。
- `age_verified` 与 `player_control_preserved` 必须为 true 才能作为有效 checkpoint。
- `force_full` 可由换场、参与者变化、边界增删、60 分钟以上时间跨度、跨天、定期校准，或 patch/`--full` 显式请求触发。`commit_turn.py` 不落盘中间态：提交后可见 `force_full: false`、`force_reason: null`，`last_full_turn` 为本次校准回合，`next_full_turn` 为本次校准回合 + 5。长时间快进、跨天和载入后的必要全量追算由提交器自动触发；只有需要覆盖自动判定时才显式传 `force_full: true`。

## 历史压缩

`resolved_summary` 只保存已经解决、结果稳定、且不再直接驱动当前人物决策的历史摘要。每项必须保存稳定事件 ID、解决回合和非空结果：

```yaml
- event_id: evt-004
  resolved_turn: 9
  outcome: "实际兑现结果"
```

摘要可以合并旧记忆，但不得替代当前 active 状态。未兑现的跨回合承诺、pending 事件、active 边界、安全状态、冷却和 checkpoint 不得压缩或删除；当前互动判断不单独落盘。

## 保存检查

保存前必须先完成预演、校验和原子提交；校验失败不得输出伪存档。

### 机器检查

在 Skill 根目录运行：

```powershell
python scripts/validate_state.py --profile save path/to/save.yaml
python scripts/live_slice.py saves/current_state.yaml --human
```

开局另用 `python scripts/build_opening.py --complete` 或 `python scripts/validate_state.py --profile opening path/to/opening.yaml`；不要把 `--complete` 放进保存前检查，它会覆盖工作活档。

开局提交使用同一校验器的 `opening` profile；保存与载入使用 `save` profile，不得用不同 schema 绕过共享引用与安全检查。覆盖保存经 `manage_saves.py save <slot> <file> --expected-updated-at <载入时观察值>` 执行，冲突处理见「存档槽与冲突检测」。

所有结构、类型、枚举、唯一 ID、角色引用、事件引用、时间差、年龄和 checkpoint 约束，以该脚本输出为唯一机器判定来源。脚本返回对应 profile 的 `OK: <profile> invariants validated` 后，才可把状态写入槽位。玩家可见回执以 `SKILL.md` 输出规范为准。

缺少依赖时先运行 `python -m pip install -r requirements.txt`。

### 人工语义检查

以下语义检查按风险执行；新开局和载入至少检查年龄、安全状态、当前世界一致性和可接续节点，保存时优先检查本回合发生变化的区域。只有排错或高风险结构变更时才执行完整清单：

1. 年龄确实来自游戏中已明确确认的成年信息，不是为通过校验临时填入的数字。
2. `world.constants`、张力引擎、身份、处境和关系仍描述同一个世界，没有用占位词掩盖未决定内容。
3. 每条 active 边界都是玩家明确提出且仍有效的硬边界；撤销边界保留历史，不会被误当作 active。
4. 当前互动判断必须结合参与者、地点、行为、明确反应和撤回信号；换场不继承旧场景的互动判断。
5. `current_node.unresolved_action` 停在玩家可以接手的位置，没有替玩家完成交易、换场或关键选择。
6. 未兑现的跨回合承诺和事件都有可理解的触发条件、稳定 ID 和未兑现的实际理由；没有用承诺掩盖本回合未兑现。
7. `resolved_summary` 只包含稳定历史，不包含仍会改变未来决策的内容。
8. 存档可从当前节点直接接续，不需要重掷开局或重建角色。

## 载入流程

1. 先确定当前会话绑定的存档；没有明确目标且上下文不存在唯一绑定槽时，不得猜测写入目标。
2. 载入命名存档时读取槽位 `manifest.yaml`，记录 `updated_at` 供保存时冲突检测。
3. 检测顶层 `save_version`；含该字段的输入不得解释为“解除暂停”。
4. 只接受 `save_version: 3`；缺失、旧版本或未知版本均停止载入并说明原因，不自动迁移。
5. 运行对应 profile 的机器校验；按载入风险检查年龄、安全状态、世界一致性、未兑现事件和当前接续点。只有校验失败、排错或高风险结构变更时才执行完整人工清单；错误先报告并修复，不生成正文。
6. 用存档重建世界、玩家、NPC、关系、事件队列、时钟和 checkpoint；未兑现事件继续约束后续追算，不重建或更换 ID。
7. 不重新掷骰，不重新生成角色，不改变已提交结果。
8. 从 `current_node.unresolved_action` 前一刻继续。
9. 若 `safety_state` 不是 running，只允许非亲密叙事或元指令。
10. 载入本身不增加回合，不重述完整存档，直接接续正文。
11. 若 `meta.turn` 为 0，用人话说明这是旧口径开局档，按回合 1 接续，不重掷、不自动改写文件。

如果存档无法通过校验，保留原文，逐项列出错误路径和修复要求；修复完成前不得擅自猜测字段或推进剧情。

## 旧档兼容说明

- 旧存档可能含顶层 `directives`；新局不得写入，载入时只读、不追加。`opening` profile 遇到非空 `directives` 仍应拒绝，`save` profile 只为兼容而忽略它。
- 历史事件的 `source` 可能使用 `directive:<id>` 前缀；新流程只创建 `system`、`turn`、`npc` 或 `world` 前缀，不改写旧事件 ID。
- `retcons` 是可选的改写档记录，形如 `[{turn, note}]`；只记录已提交的改写，不回退 `meta.turn`，无改写时省略。
- `meta.mode` 与 `meta.tier` 目前保留用于校验和兼容；它们不改变脚本分支行为，开局骨架仍固定写入 `mode: reliable`、`tier: 1`。
