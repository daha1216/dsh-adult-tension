# 状态总结与恢复

## 职责与原则

存档必须让一个新实例直接重建当前状态，而不是重放历史。载入时不得重新执行开局、重新抽取角色、重掷随机结果或改变已提交结果。

命令语义、玩家可见输出、回合事务和安全不变量以 `SKILL.md` 为准；时间、Tier 追算、事件处理和历史压缩以 `references/世界运转.md` 为准；角色字段以 `references/角色设计.md` 为准。本文件只规定 v3 存档结构、持久化语义、保存检查和恢复流程。

机器可验证的结构、类型、枚举、引用和时序约束，以 `scripts/validate_state.py` 的执行结果为唯一准则；本文件不复制一套平行的机器 schema。

以下信息不可压缩：

- 角色稳定 ID、姓名和已确认年龄
- 世界常量、张力引擎、当前壳与压力种子
- active 玩家硬边界
- 当前场景的同意记录与安全状态
- 当前模式、Tier、`simulation`、回合号和世界时钟
- NPC 核心字段、近期记忆和自主冷却
- 顶层关系图中仍会影响传播或决策的关系边
- pending 指令、其兑现事件、pending 事件和远程钩子
- 最近一次完整 checkpoint
- `current_node` 的可恢复接续点

## 字段枚举速查

以下枚举与 `scripts/validate_state.py` 的常量对应；新增或修改取值时必须同步脚本、文档和测试。

| 字段 | 合法取值 |
|---|---|
| `meta.mode` | `reliable` / `immersive` |
| `meta.tier` | `1` / `2` / `3` |
| `meta.power_structure` | `player_high` / `npc_high` / `equal` / `switchable` |
| `meta.safety_state` | `running` / `paused` |
| `boundaries[].status` | `active` / `revoked` |
| `consent.grants[].status` | `unknown` / `granted` / `withdrawn` / `not_applicable` |
| `events[].kind` | `immediate` / `near` / `far` / `timed` / `probabilistic` |
| `events[].status` | `pending` / `resolved` / `cancelled` |
| `npcs[].role_level` | `main` / `important_supporting` / `supporting` |
| `directives[].kind` | `action` / `outcome` / `canon` / `retcon` / `style` |
| `directives[].status` | `pending` / `fulfilled` / `blocked` |
| `directives[].deadline` | `current_turn` / `earliest_possible` |
| `directives[].adaptation_scope[]` | `world` / `player` / `npc` / `relationship` / `event` / `scene` |
| `directives[].block_code` | `adult_requirement` / `safety_paused` |

NPC 的 `sexuality_development.plasticity`、`trend` 及各个 main 专属对象的内部结构，以 `references/角色设计.md` 为准；本文件只要求这些对象在需要时持久化。

## 同意记录

本文件只规定同意记录如何持久化；场景许可的判定以 `SKILL.md` 为准。

1. 场景、地点或参与者变化时生成新 `scene_id`。
2. 每条许可保存稳定 ID、`scene_id`、参与者、明确范围、`status`、授予回合和最后确认回合。
3. 仅覆盖当前 scene、全部参与者与当前行为范围的 `granted` 有效。
4. 撤回改为 `withdrawn` 并保留记录，但只在同一 scene 内保留；换场景后 `grants` 只保存当前 scene 记录，旧记录需另行归档。
5. 参与者必须是已存在角色，并全部位于 `current_node.participants`；不得用场外角色的许可支持当前场景。

## 玩家指令记录

`directives` 是可选扩展；无有效叙事指令时可为空或省略，一旦建立指令契约，尤其是跨回合 `pending` 契约时必须保存。

1. `required_outcome` 保存不可被 NPC、随机结果或旧计划否决的目标；`protected_details` 保存玩家明确指定且不可偷换的细节。
2. `adaptation_scope` 记录因果桥允许改动的状态域。
3. `current_turn` 契约提交时不得仍为 `pending`。跨回合 pending 必须使用 `earliest_possible`，并引用已有 pending 事件；该事件的 `source` 必须等于指令 ID。
4. `fulfilled` 必须保存实际兑现结果；`blocked` 只允许年龄要求或暂停安全状态两种硬阻断，并保存阻断说明。其他剧情冲突必须适配，不得 blocked。
5. 指令 ID 全局唯一。重复处理同一指令时复用原 ID 和事件，不重复创建结果。
6. fulfilled/blocked 记录在结果稳定后可压缩进 `resolved_summary`；pending 记录及其兑现事件不可压缩。

## 叙事表现类可选扩展字段

以下字段只服务叙事表现，有值才保存，缺失时按默认值处理。它们不属于 v3 核心 schema，`validate_state.py` 不校验其取值。

| 字段 | 位置 | 取值 | 缺失默认 |
|---|---|---|---|
| `active_voice_mode` | 每个 NPC | `surface` / `inner` | `surface` |
| `voyeur_pov` | `meta` | `on` / `off` | `off` |

`active_voice_mode` 载入后保持存档中的状态，不重新判定，也不因载入自动退回表层。`voyeur_pov` 只影响叙述层能否展现 NPC 未表露的内心，不改变任何角色的信息集。

## 时间与 checkpoint

- `clock`、`previous_clock` 和事件 `due_at` 使用**带时区偏移**的 ISO 8601 字符串；不带偏移的本地时间不具备可恢复性。
- `delta_t` 是 `clock - previous_clock` 的非负整数秒；`delta_human` 仅供人读，可为空，不参与计算。
- 开局或无时间流逝时，`clock == previous_clock` 且 `delta_t == 0`。
- 有时间变化时，先把旧 `clock` 写入 `previous_clock`，再写新 `clock` 与对应 `delta_t`。
- `checkpoint.changed` 记录本回合重要变化的字段路径和原因，不是完整台账。
- `last_full_turn` 不得大于当前回合；`next_full_turn` 始终为 `last_full_turn + 5`。
- `age_verified` 与 `player_control_preserved` 必须为 true 才能作为有效 checkpoint。存在 `directives` 时，`directive_priority_preserved` 必须存在且为 true。
- `force_full` 由场景切换、参与者变化、边界或同意变化、快进、跨天、载入存档等事件触发；完整校准完成后重设下一次检查点。

## 压缩摘要

`resolved_summary` 只保存已经解决、结果稳定、且不再直接驱动当前人物决策的历史摘要。推荐保存：

```yaml
- id: directive-001
  kind: directive
  directive_id: directive-001
  outcome: "实际兑现结果"
  resolved_turn: 8
- id: evt-004
  kind: event
  semantic_key: "稳定的事件语义"
  outcome: "实际兑现结果"
  resolved_turn: 9
```

摘要可以合并旧记忆，但不得替代当前 active 状态。pending 指令、兑现事件、pending 事件、边界、当前许可、冷却和 checkpoint 不得压缩或删除。

## 保存检查

保存前必须先完成预演、校验和原子提交；校验失败不得输出伪存档。

### 机器检查

在 Skill 根目录运行：

```powershell
python scripts/validate_state.py path/to/save.yaml
```

所有结构、类型、枚举、唯一 ID、角色引用、同意范围、事件引用、时间差、pending 指令绑定、年龄和 checkpoint 约束，以该脚本输出为唯一机器判定来源。脚本返回 `OK: save invariants validated` 后，才可输出完整 YAML。

缺少 YAML 解析库时先运行：

```powershell
python -m pip install PyYAML
```

### 人工语义检查

机器校验通过后仍须确认：

1. 年龄确实来自游戏中已明确确认的成年信息，不是为通过校验临时填入的数字。
2. `world.constants`、张力引擎、身份、处境和关系仍描述同一个世界，没有用占位词掩盖未决定内容。
3. 每条 active 边界都是玩家明确提出且仍有效的硬边界；撤销边界保留历史，不会被误当作 active。
4. 当前场景的许可范围与参与者、地点和行为一致；没有把旧场景许可带入新场景。
5. `current_node.unresolved_action` 停在玩家可以接手的位置，没有替玩家完成交易、换场或关键选择。
6. pending 指令和事件都有可理解的触发条件、稳定 ID 和未兑现的实际理由；没有用 pending 掩盖本回合未兑现。
7. `resolved_summary` 只包含稳定历史，不包含仍会改变未来决策的内容。
8. 存档可从当前节点直接接续，不需要重掷开局或重建角色。

## 载入流程

1. 检测顶层 `save_version`；含该字段的输入不得解释为“解除暂停”。
2. 只接受 `save_version: 3`；缺失、旧版本或未知版本均停止载入并说明原因，不自动迁移。
3. 运行完整机器校验和人工语义检查；任何错误都先报告并修复，不生成正文。
4. 用存档重建世界、玩家、NPC、关系、许可、指令契约、事件队列、时钟和 checkpoint；pending 指令继续约束后续追算，不重建或更换 ID。
5. 不重新掷骰，不重新生成角色，不改变已提交结果。
6. 从 `current_node.unresolved_action` 前一刻继续。
7. 若 `safety_state` 不是 running，只允许非亲密叙事或元指令。
8. 载入本身不增加回合，不重述完整存档。

如果存档无法通过校验，保留原文，逐项列出错误路径和修复要求；修复完成前不得擅自猜测字段或推进剧情。
