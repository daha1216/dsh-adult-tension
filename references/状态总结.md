# 状态总结与恢复

## 职责与原则

存档必须让一个新实例直接重建当前状态，而不是重放历史。载入时不得重新执行开局、重新抽取角色、重掷随机结果或改变已提交结果。

命令语义、玩家可见输出、回合事务和安全不变量以 `SKILL.md` 为准；时间、Tier 追算、事件处理和历史压缩以 `references/世界运转.md` 为准；角色字段以 `references/角色设计.md` 为准。本文件只规定 v3 存档结构、持久化语义、保存检查和恢复流程。

机器可验证的结构、类型、枚举、引用和时序约束，以 `scripts/validate_state.py` 的执行结果为唯一准则；本文件不复制一套平行的机器 schema。校验器使用两种 profile：`save` 用于已有存档的完整恢复校验，`opening` 用于回合 1 开局提交；两者共享同一核心结构和引用约束，`opening` 额外要求开局三勾、命名审计、步骤 6-9 产物及首次深度校准。

## 存档槽与并发提交

v3 YAML 是叙事状态本体，不包含会话锁。持久化层使用以下布局：

```text
saves/
  slots/
    <slot>/
      state.yaml       # save_version: 3，继续用 save profile 校验
      manifest.yaml    # manifest_version、slot、created_at、updated_at
      .write.lock      # 仅供 manage_saves.py 使用的进程锁
```

`scripts/manage_saves.py` 是命名存档的初始化、列出、载入与原子写入实现入口。每个会话默认绑定自己的存档；载入时记录 `manifest.updated_at`，保存时必须携带载入时观察到的 `updated_at`。槽位已被其他窗口写入（`updated_at` 不一致）时拒绝覆盖，不自动合并两个窗口的状态；需要保留两种走向时，把当前版本另存为其他名称。`.write.lock` 只保护存储提交，不增加回合，也不改变叙事状态字段。

以下信息不可压缩：

- 角色稳定 ID、姓名和已确认年龄
- 世界常量、张力引擎、当前壳与压力种子
- active 玩家硬边界
- 当前场景的同意记录与安全状态
- 当前模式、Tier、`simulation`、回合号和世界时钟
- NPC 核心字段、近期记忆和自主冷却
- 顶层关系图中仍会影响传播或决策的关系边
- 未兑现的跨回合承诺、pending 事件和远程钩子
- 最近一次完整 checkpoint
- `current_node` 的可恢复接续点

## 字段枚举速查

以下枚举与 `scripts/validate_state.py` 的常量对应；新增或修改取值时必须同步脚本、文档和测试。

| 字段 | 合法取值 |
|---|---|
| `meta.mode` | `reliable` / `immersive` |
| `meta.tier` | `1` / `2` / `3` |
| `meta.power_structure` | `player_high` / `npc_high` / `equal` / `switchable` |
| `meta.safety_state` | `running` / `paused` |
| `boundaries[].status` | `active` / `revoked` |
| `consent.grants[].status` | `unknown` / `granted` / `withdrawn` / `not_applicable` |
| `events[].kind` | `immediate` / `near` / `far` / `timed` / `probabilistic` |
| `events[].status` | `pending` / `resolved` / `cancelled` |
| `npcs[].role_level` | `main` / `important_supporting` / `supporting` |

事件 `source` 的 `type:id` 前缀为 `system` / `turn` / `npc` / `world`；`directive` 前缀仅为兼容历史存档保留，新流程不得创建。新局 `opening` profile 若出现非空 `directives` 即校验失败；`save` profile 仍忽略旧档中的该字段。

NPC 的 `sexuality_development.plasticity`、`trend` 及各个 main 专属对象的内部结构，以 `references/角色设计.md` 为准；本文件只要求这些对象在需要时持久化。

同一 `semantic_key` 不得对应多个事件；`pending` 事件必须携带非空 `semantic_key`，已解决或已取消事件可在压缩前省略。

## 同意记录

本文件只规定同意记录如何持久化；场景许可的判定以 `SKILL.md` 为准。

1. 场景、地点或参与者变化时生成新 `scene_id`；`consent.scene_id`、`consent.location`、`consent.participants` 必须分别与 `current_node` 的三个字段完全一致，并在同次提交更新。
2. 每条许可保存稳定 ID、`scene_id`、参与者、`scope` 映射列表、`status`、授予回合、撤回回合和最后确认回合。
3. `scope` 的每项必须是 `{type, permission}` 映射，`type` 仅 `scene|physical|emotional|information`，`permission` 为非空的明确许可说明。
4. 仅覆盖当前 scene、当前地点、全部参与者与当前行为范围的 `granted` 有效。
5. 撤回改为 `withdrawn` 并写入 `withdrawn_turn`；其他状态的 `withdrawn_turn` 必须为 null。换场景后 `grants` 只保存当前 scene 记录，旧记录需另行归档。
6. 参与者必须是已存在角色，并全部位于 `current_node.participants`；不得用场外角色的许可支持当前场景。
7. 相邻私密空间、参与者不变、无人撤回且未暂停时，可将上一场景 granted 的 physical 许可复制到新 `scene_id`（新 grant id，`inherited_from` 指向旧 id），范围不扩大。走廊、公共空间或第三人加入仍重置。

## 可选扩展字段

以下字段只服务叙事，有值才保存，缺失时按默认值处理。它们不属于 v3 核心 schema，`validate_state.py` 不校验其取值。

| 字段 | 位置 | 取值 | 缺失默认 |
|---|---|---|---|
| `active_voice_mode` | 每个 NPC | `surface` / `inner` | `surface` |
| `voyeur_pov` | `meta` | `on` / `off` | `off` |
| `function` | 每个 NPC | 非空字符串 | 无（角色功能不明确时不写） |
| `appellation` | `player` | 非空字符串 | 按姓名与身份自然称呼 |
| `inherited_from` | `consent.grants[]` | 原 grant id | 无（非继承许可不写） |

`active_voice_mode` 载入后保持存档中的状态，不重新判定，也不因载入自动退回表层。`voyeur_pov` 只影响叙述层能否展现 NPC 未表露的内心，不改变任何角色的信息集。

## 时间与 checkpoint

- `clock`、`previous_clock` 和事件 `due_at` 使用**带时区偏移**的 ISO 8601 字符串；不带偏移的本地时间不具备可恢复性。
- `delta_t` 是 `clock - previous_clock` 的非负整数秒；`delta_human` 仅供人读，可为空，不参与计算。
- 开局或无时间流逝时，`clock == previous_clock` 且 `delta_t == 0`。开局之后的普通行动默认 `delta_t` 为 60–900 秒；「继续」必须让时钟变化。
- 有时间变化时，先把旧 `clock` 写入 `previous_clock`，再写新 `clock` 与对应 `delta_t`。
- `checkpoint.changed` 记录本回合重要变化的字段路径和原因，不是完整台账。
- `last_full_turn` 不得大于当前回合；`next_full_turn` 始终为 `last_full_turn + 5`。
- `age_verified` 与 `player_control_preserved` 必须为 true 才能作为有效 checkpoint。
- `force_full` 由场景或地点切换、参与者变化、边界或同意变化、指令适配改写世界常量/身份/能力/关系、快进、跨天、载入存档等事件触发。触发时先置为 true，并以非空 `force_reason` 写明触发原因；完成深度校准后写入 `last_full_turn`、将 `next_full_turn` 重设为当前回合 + 5，再将 `force_full` 复位为 false 且 `force_reason` 复位为 null。

## 压缩摘要

`resolved_summary` 只保存已经解决、结果稳定、且不再直接驱动当前人物决策的历史摘要。每项必须保存稳定事件 ID、解决回合和非空结果：

```yaml
- event_id: evt-004
  resolved_turn: 9
  outcome: "实际兑现结果"
```

摘要可以合并旧记忆，但不得替代当前 active 状态。未兑现的跨回合承诺、pending 事件、边界、当前许可、冷却和 checkpoint 不得压缩或删除。

## 保存检查

保存前必须先完成预演、校验和原子提交；校验失败不得输出伪存档。

### 机器检查

在 Skill 根目录运行：

```powershell
python scripts/validate_state.py --profile save path/to/save.yaml
python scripts/validate_state.py --profile opening path/to/opening.yaml
python scripts/manage_saves.py load <slot>
```

开局提交使用同一校验器的 `opening` profile；保存与载入使用 `save` profile。调用时以脚本实际支持的 profile 参数为准，二者不得用不同 schema 绕过共享引用与安全检查。保存通过 `manage_saves.py save <slot> <file> --expected-updated-at <载入时观察值>` 执行；`updated_at` 与载入时不一致时只报告冲突，不输出伪存档、不覆盖新版本。

所有结构、类型、枚举、唯一 ID、角色引用、同意范围、事件引用、时间差、年龄和 checkpoint 约束，以该脚本输出为唯一机器判定来源。脚本返回对应 profile 的 `OK: <profile> invariants validated` 后，才可把状态写入槽位。「存档 / 保存 / qs」只向玩家回一句话确认；完整 YAML 仅在「导出存档」时输出。槽名允许中文，空格改成 `-`。

缺少 YAML 解析库时先运行：

```powershell
python -m pip install PyYAML
```

### 人工语义检查

机器校验通过后仍须确认：

1. 年龄确实来自游戏中已明确确认的成年信息，不是为通过校验临时填入的数字。
2. `world.constants`、张力引擎、身份、处境和关系仍描述同一个世界，没有用占位词掩盖未决定内容。
3. 每条 active 边界都是玩家明确提出且仍有效的硬边界；撤销边界保留历史，不会被误当作 active。
4. 当前场景的许可范围与参与者、地点和行为一致；没有把旧场景许可带入新场景。
5. `current_node.unresolved_action` 停在玩家可以接手的位置，没有替玩家完成交易、换场或关键选择。
6. 未兑现的跨回合承诺和事件都有可理解的触发条件、稳定 ID 和未兑现的实际理由；没有用承诺掩盖本回合未兑现。
7. `resolved_summary` 只包含稳定历史，不包含仍会改变未来决策的内容。
8. 存档可从当前节点直接接续，不需要重掷开局或重建角色。

## 载入流程

1. 先确定当前会话绑定的存档；未明确存档时不得猜测并写入全局文件。
2. 载入命名存档时读取槽位 `manifest.yaml`，记录 `updated_at` 供保存时冲突检测。
3. 检测顶层 `save_version`；含该字段的输入不得解释为“解除暂停”。
4. 只接受 `save_version: 3`；缺失、旧版本或未知版本均停止载入并说明原因，不自动迁移。
5. 运行完整机器校验和人工语义检查；任何错误都先报告并修复，不生成正文。
6. 用存档重建世界、玩家、NPC、关系、许可、事件队列、时钟和 checkpoint；未兑现事件继续约束后续追算，不重建或更换 ID。
7. 不重新掷骰，不重新生成角色，不改变已提交结果。
8. 从 `current_node.unresolved_action` 前一刻继续。
9. 若 `safety_state` 不是 running，只允许非亲密叙事或元指令。
10. 载入本身不增加回合，不重述完整存档。可附一次【此刻】。
11. 若 `meta.turn` 为 0，用人话说明这是旧口径开局档，按回合 1 接续，不重掷、不自动改写文件。

如果存档无法通过校验，保留原文，逐项列出错误路径和修复要求；修复完成前不得擅自猜测字段或推进剧情。
