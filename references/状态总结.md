# 状态总结与恢复

## 原则

存档必须让一个新实例直接重建当前状态，而不是重放历史。载入存档时不得重新执行完整开局、重新抽取角色或改变已提交结果。

命令语义、玩家可见输出、回合事务和安全不变量以 `SKILL.md` 为准；本文件只规定存档结构、迁移、保存检查和恢复所需的持久化信息。

以下字段不可压缩：角色稳定 ID、明确年龄、世界常量、玩家硬边界、逐场景逐参与者的同意记录、安全状态、模式、Tier、追算开关（`simulation`）、回合号、NPC 核心字段、自主冷却、pending 事件、远程钩子和最近一次完整 checkpoint。

## 同意记录

本文件只规定同意记录如何持久化；场景许可的判定以 `SKILL.md` 不变量为准。

1. 场景、地点或参与者变化时生成新 `scene_id`。
2. 每条许可保存稳定 ID、`scene_id`、参与者、明确范围、`status`、授予回合和最后确认回合。
3. `status` 仅 `unknown|granted|withdrawn|not_applicable`。
4. 仅覆盖当前 scene、全部参与者与当前行为范围的 `granted` 有效。
5. 撤回改为 `withdrawn` 并保留记录，不删除；此保留仅在**同一 scene 内**。换场景生成新 `scene_id` 时，`consent.grants` 只保留当前 scene 的记录，旧场景记录不再留在 `grants` 里（如需追溯另行归档）。这样才能通过 `scripts/validate_state.py` 对每条 grant 的 `scene_id` 必须等于当前 `consent.scene_id` 的校验。

## 后台校准

校准的执行顺序和触发条件以 `SKILL.md`「每回合事务」为准；存档只保留校准结果：`checkpoint.changed` 记录本回合的重要字段变化，完整校准完成后更新 `last_full_turn` 和 `next_full_turn`。
## 保存检查

以下是 v3 存档必须满足的持久化约束；具体错误以 `scripts/validate_state.py` 的机器校验结果为准。

1. `save_version` 必须等于 `3`，根节点必须是合法 YAML 映射。
2. 玩家和每个 NPC 都必须有唯一稳定 ID，年龄必须是明确且大于等于 18 的整数；布尔值不算整数。
3. 角色、边界、同意和事件 ID 在全局范围内不得重复。
4. active 边界必须有非空主题；边界状态只能是 `active|revoked`。
5. 每条同意记录必须绑定当前场景中的至少两名不重复参与者，并有明确范围；当前场景之外的记录不能作为当前许可。
6. `meta` 各字段须为合法值：`mode` ∈ {reliable, immersive}、`tier` ∈ {1,2,3}、`power_structure` ∈ {player_high, npc_high, equal, switchable}、`simulation` 为布尔，`safety_state` 只能是 `running|paused`。
7. 时间字段使用 ISO 8601 字符串；`clock` 不早于 `previous_clock`，`world.delta_t` 等于两者差值的非负整数秒，`delta_human` 可为空。
8. 每个 NPC 必须保存 `role_level` 和完整自主冷却；`main` 必须保存身份档、处境、决策卡、亲密画像、发展状态和命名审计。关系只以顶层 `relationships` 为正式来源，端点必须指向已存在角色且不得自指，信任值必须在 -5..+5。
9. 事件状态只能是 `pending|resolved|cancelled`；pending 事件必须有非空触发条件或到期时间，创建回合不得晚于当前回合。
10. `world.pressure_seeds.near_event_id` 和 `far_event_id` 若非空必须引用已有事件；远程钩子必须与 `hook: true` 一致。
11. 当前节点只能引用已存在的角色，必须保存可恢复的当前处境，并且能明确接续而不替玩家作关键决定。
12. `checkpoint.last_full_turn` 不得大于当前回合，`next_full_turn` 须等于 `last_full_turn + 5`；四项 invariants 必须存在且为布尔值。

保存后，在 Skill 根目录运行：

```powershell
python scripts/validate_state.py path/to/save.yaml
```

缺少 YAML 解析库时先运行：

```powershell
python -m pip install PyYAML
```

## 载入流程

1. 检测顶层 `save_version`；含该字段的输入不得解释为“解除暂停”。
2. 若为 v2，按下节人工迁移成 v3；本 Skill 不提供自动迁移脚本。未知版本停止载入并说明原因。
3. 运行完整保存检查；任何错误都先报告并修复，不生成正文。
4. 用存档重建世界、玩家、NPC、关系、许可和事件队列。
5. 不重新掷骰，不重新生成角色，不改变已提交结果。
6. 从 `current_node.unresolved_action` 前一刻继续。
7. 若 `safety_state` 不是 running，只允许非亲密叙事或元指令。
8. 载入本身不增加回合，不重述完整存档。

## v2 迁移到 v3

按以下顺序迁移，不得静默猜测：

1. 把 `save_version` 改为 `3`。
2. 若旧存档使用 `players` 列表，只在列表恰好有一项时改名为 `player`；否则停止并要求用户确认玩家主体。
3. 生成稳定 `consent.scene_id`。旧版全局 `consent.scene` 无法证明具体参与者和范围，因此不要自动迁移成 `granted`。
4. 将 `consent.grants` 初始化为空列表，把 `meta.safety_state` 设为 `paused`，并要求玩家重新确认当前场景参与者和许可范围。
5. 保留角色、边界、事件、关系、冷却、世界常量和 current_node，不重新生成 ID。
6. 缺少的冷却字段采用保守值：`last_turn=null`、`recent_turns=[]`、`cooldown_until=当前回合`。
7. 无法可靠推断的年龄保留为 `null`，停止相关内容并要求明确成年年龄；不得默认填 18。
8. 迁移后运行 v3 完整校验，通过后才允许接续。

v1 或未知结构没有足够稳定的字段映射，不自动迁移。保留原文，列出缺失字段并等待用户确认。
