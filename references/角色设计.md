# 角色设计

本文件只负责人物层：生成原则、起名、人物决策轴、主 NPC 角色卡、身份档、处境档、亲密画像、决策卡、角色层级、配角和玩家化身。执行时机、结构骰与开局校验以 `references/开局流程.md` 为准；身份、处境与壳的抽样表见 `references/素材库.md`；安全不变量以 `SKILL.md` 为准。

主要角色和亲密互动参与者必须明确为 18 岁以上；校园、社团、学园或师生意象须声明为成年人教育、职业培训或成年社群。

## 人物生成原则

先生成普通人格、目标、底线和生活处境，再独立生成亲密画像。亲密画像不能覆盖人物原本的职业、道德、关系目标或日常行为，也不能从普通人格直接推导。

禁止以下绑定：

```text
善良 ≠ 保守
单纯 ≠ 欲望低
经验少 ≠ 表现被动
表现大胆 ≠ 对所有人开放
欲望强 ≠ 自控差
低欲望 ≠ 等待被改变
亲密偏向 ≠ 当前许可
```

生成时先抽取宽泛倾向，再分别生成各字段。倾向只调整概率，不锁定结果；主 NPC 可提高少见组合概率，普通配角以自然普通为主。同局人物不得全部使用同一倾向。

```yaml
profile_weights:
  ordinary_natural: 35
  reserved_sensitive: 15
  inexperienced: 12
  experienced_restrained: 10
  open_active: 8
  playful: 8
  conflicted: 7
  low_desire: 5
```

所有画像仅用于明确为成年人的虚构角色。知识少、经验少、单纯或不懂世事不得被解释为年龄不明或未成年。

## 表层风味（可选）

生成主 NPC 或重要配角时，可为每人抽取一项表层风味。风味只影响语言滤镜（9f）、标志动作和相处质感，不改变人格、目标、底线、亲密画像或许可判定：

傲娇、冷娇、天然呆、腹黑、三无、姐御、大小姐、元气、病弱、毒舌、忠犬、小恶魔、温柔年上、装酷内热、正经人崩坏、慵懒摸鱼、社恐结巴、笑面藏刀、中二、俺样、天然黑、书呆子、武痴、吃货、戏精、系统自拟

同局不同角色不得重复同一风味；风味与亲密画像分别独立抽取，抽取遵循 `references/开局流程.md`「随机性与多样性协议」。美学基调为写实或文学向时可跳过本步（写 `—`）。

## 外观与气质轴（可选）

生成主 NPC 或重要配角时，可从不同轴各抽一项，主 NPC 至多两项显著特征，配角至多一项。外观只提供画面质感与辨识度，不反推性格、身份、亲密画像或许可；现实档中的非自然发色瞳色写为染发、美瞳，或顺延为自然色。

- 发色：黑、深棕、亚麻、银白、铂金、酒红、蓝紫、粉、渐变、内侧挑染
- 发型：长直、短碎、高马尾、双马尾、编发、波浪卷、丸子头、狼尾、及肩内扣、寸头
- 瞳与面部：琥珀瞳、深黑瞳、灰蓝瞳、异色瞳、泪痣、虎牙、下垂眼、锐利吊眼、无高光眼、雀斑
- 体型气质：高挑、娇小、健壮、柔韧、丰腴、清瘦、端正、慵懒、锋利、温吞
- 标志配饰：眼镜、发饰、耳骨钉、旧手表、护身符、露指手套、发带、徽章、围巾、创可贴

## 口癖与语感（可选）

9f 语言滤镜可为主 NPC 或重要配角加抽一项口癖或语感特征；同局不重复，与风味、画像互不推导，写实或文学向可跳过：

句尾口癖、敬语过剩、突然方言、比喻控、极简应答、语速过快、书面语腔、委婉绕圈、拟声词多、总在道歉、称呼独特、无敬语直呼

## 人物决策轴

为主 NPC 逐轴抽取；配角只取核心价值与压力策略。它们是生成目标、底线和决策卡的种子，不新增存档字段，也不推导亲密画像或当前许可。

- 核心价值：自由、责任、归属、真相、秩序、成就、公平、安稳、照顾他人、自我证明
- 压力策略：正面解决、谈判交换、隐瞒拖延、寻求帮助、独自承担、转移风险、收集证据、先退后进、用行动代替解释、维持表面稳定
- 关系姿态：谨慎试探、直接合作、保持距离、过度负责、习惯掌控、害怕亏欠、先信后验、先验后信、用玩笑降温、用规则保护双方

同局角色尽量不重复同一组合。将核心价值落实为“最想守住什么”，将压力策略落实到 `pressure_response` 和 `action_preferences`，将关系姿态落实为可观察的接近或退让方式；不得把标签原样堆进人物介绍。

## 名字生成与去重

起名是开局关卡，不是润色。名字由生活背景决定，不由性格、欲望或反差设定决定。禁止跳过、后补或先写正文再起名。

### 分层要求

| 角色 | 流程 | 候选 | 审计深度 |
|---|---|---|---|
| 主 NPC | 标准起名 | ≥3 | 标准 `naming_audit` |
| 未预锁玩家化身 | 标准起名 | ≥3 | 标准 `naming_audit` |
| 预锁玩家姓名 | 合规与去重 | — | `locked_by_player: true` + checks |
| 配角 | 简起名 | ≥2 | 简 `naming_audit` |

时机：9a 先完成主 NPC 起名再写年龄/身份；步骤 13 每名配角先简起名；玩家化身按上表。开局校验时任一起名不合格则 `validation.passed: false`。

### 标准起名（主 NPC / 未预锁玩家）

1. 建立 `name_profile`（culture / region / era / social_context / usage）。
2. 生成至少 3 个符合背景的候选（中文：先姓后名再组合）。
3. 排除同局重名、读音冲突、文化明显不符或象征意味过强的候选。
4. 在剩余候选中选择最自然、最符合角色生活背景且便于区分的姓名；不得按性格、外貌或“最有故事感”选名。
5. 写入 `naming_audit` 与姓名字段后，才写其余人物字段。

### 简起名（配角）

1. 继承本局主文化/地区/年代，可只写精简 `name_profile`。
2. 生成至少 2 个更常见、易区分的候选。
3. 选择与同局不冲突、自然普通的姓名，不做分项评分。
4. 写入简审计后继续配角其余字段。

### 审计结构

标准与简起名共用同一结构，用 `mode` 区分：

```yaml
naming_audit:
  role_ref: main_npc|player|supporting
  mode: standard|lite            # 主 NPC / 未预锁玩家 = standard；配角 = lite
  name_profile: {culture: null, region: null, era: null, social_context: null, usage: legal_name}
  candidates:                    # standard ≥3；lite ≥2
    - {name: null, reject_reason: null}
  chosen: null
  checks:
    same_cast_duplicate: pass|fail
    phonetic_clash: pass|fail
    culture_match: pass|fail
    natural_fit: pass|fail
    supporting_plainer: pass|fail|n_a   # 仅 lite 检查；standard 写 n_a
  recent_check: checked|unavailable
  locked_by_player: false
```

标准失败条件：无 `name_profile`；候选 <3；`chosen` 为空；任一项 checks 为 fail；按人设/外貌选名；明显不符合生活背景。
简起名失败条件：候选 <2；`chosen` 为空；与同局重名或读音冲突；明显不符合文化或时代背景；`supporting_plainer` 为 fail。

### 姓名字段

```yaml
legal_name: null
public_name: null
nickname: null
alias: null
```

只填剧情需要的字段。`naming_audit.chosen` 默认写入 `legal_name`。近期记录仅参与去重，不得改写预锁姓名。命名检查直接依据角色所在文化、地区、年代和社会背景，不依赖外部命名权重文件。

## 主 NPC 全维角色卡

### 9a-9g

| 子步 | 内容 |
|---|---|
| 9a | 标准起名后写入姓名、年龄（≥18）、身份（按「身份档」补齐）、公开名声 |
| 9b | 处境类型、具体压力、局势句（按「处境档」补齐） |
| 9c | 人物决策三轴，再加可选反差轴（抽样表见本文件与 `references/素材库.md`；均不锁定亲密画像） |
| 9d | 亲密画像开局核心子集与变化基线 |
| 9e | 对玩家初始关系 −5..+5，并写出原因 |
| 9f | 语言滤镜：句长、礼貌度、回避方式、压力下口吻；抽取了表层风味时须在此体现 |
| 9g | 生成清单核对（索引，不重复写内容） |

9a 先完成标准起名再写其余字段。禁止先定人设/反差/画像再回头配名。无合格姓名不得进入 9b。

### 9g 生成清单

作为核对索引，确认下列已有结果（勿再生成第二套卡）：

1. 外貌与可识别细节（可抽「外观与气质轴」）
2. 核心性格，以及核心价值、压力策略和关系姿态的具体表现
3. 目标与利害
4. 底线与拒绝方式
5. 标志动作
6. 语言滤镜
7. 已知/未知信息
8. 近期记忆 1-2 条
9. 当前情绪
10. 资源与把柄
11. 地点与行动窗口
12. 亲密边界与撤回信号（关系阶段≠当前同意）
13. 亲密核心画像与变化基线
14. 自主冷却初始值

## 身份档（identity_profile）

先选择身份族，再选择或自拟具体身份（抽样表见 `references/素材库.md`「身份侧」）。身份必须能解释角色拥有的资源、限制与社会风险。生成后只需补齐以下最小关系：

```yaml
identity_profile:
  public_identity: null
  actual_function: null
  authority_source: null
  key_resource: null
  limitation: null
  obligation: null
  social_risk: null
  hidden_mismatch: null
  public_reputation: null
  private_context: null
  exposure_risk: null
```

`hidden_mismatch` 可为空，不要求每名角色都有隐藏身份。区分「侍奉与身契」与「成人行业与私密服务」时看人身关系：前者含依附或契约义务，后者是可自主进出的职业。身份侧只描述“这个人凭什么能做什么”，不替代处境压力、角色态度或许可判定。

涉及反差时，先生成公开身份与私下场景的差异，再由独立亲密画像决定欲望与表现；身份不等于性感或许可，`exposure_risk` 只表示暴露代价。

## 处境档（situation）

处境只决定角色正在承受的压力，不决定服从或许可（抽样表见 `references/素材库.md`「处境侧」）。正式结果只需补齐以下字段：

```yaml
situation:
  type: null
  trigger: null
  pressure: null
  immediate_objective: null
  deadline: null
  unresolved_choice: null
  knowledge_gap:
    player_knows: []      # 例：对方的真实身份
    npc_knows: []         # 例：门外还有第三方在等
    both_mistake: []      # 例：双方都以为对方已同意
  exits:
    available: true
    cost: null
    blocked_by: null
  consequence:
    immediate: null
    near_term: null
```

`type` 说明处境形态，`trigger` 说明刚刚发生的事，`pressure` 说明当前压力，`immediate_objective` 说明角色眼下想解决什么，`deadline` 和 `unresolved_choice` 共同制造行动窗口。`knowledge_gap` 只描述信息差，不替角色补写意志。

`exits` 必须明确暂停、离开或拒绝的可能；环境压力不自动变成许可。`consequence` 只写不处理的剧情后果。

生成局势句：

```text
<角色> 因为 <触发事件>，正在 <地点/关系> 中面对 <当前压力>；
必须在 <期限> 前决定 <未完成选择>，否则 <可见后果> 将发生。
```

## 亲密画像与变化

开局只生成核心子集；进入亲密线后再按需展开。画像描述欲望与表达，许可判定只按 `SKILL.md`。

### 开局核心子集（主 NPC 必填）

```yaml
sexuality_profile:
  drive:
    intensity: low|medium|high
    awareness: unaware|uncertain|clear
  preferences:
    initiative: follow|responsive|lead|switch
    pace: gradual|adaptive|direct
    style: tender|natural|playful|intense|experimental|mixed
  expression:
    directness: reserved|natural|direct|uninhibited
  regulation:
    self_control: stable|variable|poor
  interest_origin:
    type: stable|contextual|unexplored|defensive|target_specific
    reason: null   # 例：只对特定对象、源于某段经历、尚未探索
```

重要配角：开局可用同结构核心子集。普通功能配角：仅在剧情需要时生成精简画像。

### 按需展开（进入亲密线后）

需要更细写时再补，不要求开局填满：

```yaml
# 可选展开
background: {knowledge, experience, mistaken_beliefs}
preferences_extra: {emotional_link, exclusivity, novelty, turn_ons, turn_offs}
expression_extra: {teasing, verbal_expression, physical_initiative, public_mask, private_style}
regulation_extra: {inhibition, conflict_or_shame, compulsivity, aftermath_need}
```

高欲望或大胆表现不等于 `compulsivity`；只有持续失控并产生负面后果时才记录强迫风险。低兴趣时 `interest_origin` 不得默认「等待被改变」。

### 变化状态

```yaml
sexuality_development:
  baseline: {}          # 开局核心快照
  current: {}           # 当前核心快照
  plasticity: low|medium|high   # 开局可只记总可塑性；展开后再分轴
  evidence: []
  trend: stable|opening|intensifying|conflicted|retreating
```

更新 `current` 须有至少两条跨回合且方向一致的事件证据；变化来自探索或自我承认，不得因压力、边界违反或画像变化自动扩大许可。不得整卡翻转；「沉沦」只作正文主观效果。

## 角色层级与持久化

每个 NPC 保存 `role_level: main|important_supporting|supporting`，用于确定生成和存档深度。多数局只有一名主 NPC；后宫、群像或多主角局允许多名 `main`，每名都须完成完整主 NPC 全维角色卡与合格审计。

- `main`：保存完整核心字段，以及 `identity_profile`、`situation`、`decision_card`、`sexuality_profile`、`sexuality_development` 和 `naming_audit`。
- `important_supporting`：保存核心字段和决策卡；身份、处境与亲密画像按剧情相关性保存。
- `supporting`：保存年龄、身份、功能、当前位置、目标、底线、已知信息、标志细节和自主冷却；其余扩展字段可省略。

角色关系只以顶层 `relationships` 为正式来源。人物卡可在生成阶段计算初始关系，但落档后不得另存会与 `relationships` 冲突的 `relation` 数值。

## 角色决策卡

主 NPC 与重要配角保存决策卡；普通配角用精简值。运行时决策顺序以 `SKILL.md`「NPC 决策」为准。

```yaml
decision_card:
  stable_core: {identity: null, core_traits: [], hard_limits: []}
  goals: {primary: null, secondary: null, hidden: null}
  knowledge: {known: [], unknown: [], mistaken_beliefs: []}
  pressure_response: {low: null, medium: null, high: null, critical: null}
  action_preferences: {prefer: [], avoid: [], never: []}
  sexuality_refs: {profile: sexuality_profile, development: sexuality_development}
  autonomy: {last_turn: null, cooldown_until: 0}
```

`decision_card.autonomy` 只是引用摘要；自主冷却的正式来源与完整结构（含 `recent_turns`）以 `SKILL.md`「NPC 决策」的顶层 `autonomy` 为准。

人物决策轴不另存一套副卡：核心价值写入稳定核心或目标，压力策略写入压力反应与行动偏好，关系姿态只落实为性格、语言和行为证据。

## 配角

配角功能独立生成：盟友、阻力、见证者、信息源、竞争者、后果承接者、引路人、误导者、催化剂、庇护者、传话人、监视者或系统自拟。

步骤 13 顺序：功能确认 → 配角简起名 → 核心价值与压力策略 → 其余字段。每名配角保存：姓名、年龄≥18、身份、功能、与玩家/主 NPC 关系、目标、底线、已知信息、当前位置、一个标志细节。姓名必须比主 NPC 更普通。重要配角保存亲密核心子集；普通配角仅在剧情相关时生成精简画像。缺合格简审计则步骤 13 未完成。

## 玩家化身

生成前处理姓名：预锁则只合规与去重；未预锁则标准起名并写入 `naming_audit`。然后生成：

```text
player_id｜姓名｜年龄≥18｜性别/称谓｜公开身份
外貌与身体基线
可用资源 1-3 项
已知信息起点
社会处境与风险
玩家硬边界列表
```

不得替玩家补写长期目标、内心同意或不可撤回决定。
