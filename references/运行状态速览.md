# 运行状态速览

本文件是普通回合的读取白名单。它描述模型在已有活切片上继续叙事时需要关注什么，不替代 `references/状态总结.md` 的 v3 存档 schema，也不要求普通回合重新读取完整 YAML。

## 普通回合读取

优先使用 `python scripts/live_slice.py saves/current_state.yaml` 输出的活切片，按以下顺序判断：

1. **安全与时间**：`turn`、`meta.safety_state`、`simulation`、`power_structure`、`opening_mode`、`clock`、`delta_t`、`voyeur_pov`、`twist_state`。
2. **当前节点**：`current_node` 的 `location`、`scene_id`、`participants`、`node_situation`、`unresolved_action`、`last_committed_result`、`natural_next_pressure`，以及地点画像和动作元数据。
3. **当前参与者**：玩家核心信息；在场 NPC 和 main NPC 的姓名、年龄、身份、位置、性格、压力策略、目标、底线、撤回信号、情绪、近期记忆、自主冷却、身份行为、`active_voice_mode` 与亲密基线。
4. **硬边界与关系**：active 玩家边界，以及顶层 `relationships`。关系数值只读这里，不从角色卡或决策卡推导。
5. **未兑现压力**：`pending_events`。只处理仍可能改变当前决策或未来压力的事件。
6. **最近校准信号**：`checkpoint` 的 `last_full_turn`、`next_full_turn`、`force_full` 和 `changed`。`changed` 只是变化提示，不是历史台账。

`opening_mode` 区分开局压力链和自动转折规则；日常模式仍可因玩家行为、既有承诺或自然事件产生压力。

## 两种处境不可混用

- `node_situation` 来自 `current_node.situation`，是此刻场景的唯一正式来源。
- NPC 的 `situation_type` 与 `situation_pressure` 来自 `npcs[].situation`，只说明 NPC 的长期背景处境。
- 当前场景的压力、目标、信息差、退出通道和后果以 `node_situation` 为准；不要用 NPC 长期处境覆盖当前节点。

## 事件读取层级

- `pending` 事件进入普通回合上下文，按活切片顺序检查触发条件。
- 概率事件触发检查时提交 `events_update: {id, roll: true}`，不要在模型侧猜测命中结果；脚本会返回并保存 `last_roll`。
- `resolved` / `cancelled` 事件不进入普通行动上下文；只有恢复、历史压缩或深度校准时才读取。
- `checked_turns` 只用于防止同一回合重复检查，不是待处理事件。

## 普通回合不读取

除非触发深度校准，普通回合不需要读取完整 `resolved_summary`、玩家和 NPC 的 `naming_audit`、起名候选、完整 `decision_card`、亲密发展历史快照、已解决事件详情或旧档兼容字段。不要把这些内容重新拼回活切片。

## 何时升级读取

以下情况由模型先识别，脚本再做硬升级；一旦出现就按深度回合处理，并根据需要读取 `references/状态总结.md` 或 `references/世界运转.md`：

- 换场、参与者变化、NPC 自主行动或新角色进入。
- 新增、解决、取消、更新事件，或压力种子需要重指。
- 新增或撤销玩家边界，暂停/恢复安全状态，或记录改写档。
- 跨天、长时间快进、首次跨天转折，或 checkpoint 到期。
- 普通活切片缺字段、与完整存档冲突，或恢复校验失败。

普通回合只需完成当前动作、NPC反应、事件触发检查和可恢复接手点；不要为了确认稳定历史而往返读取完整存档。
