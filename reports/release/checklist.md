| 冷进程之后的 `doctor` | 76.2 ms | 94.7 ms | 107.8 ms | < 400 ms |

这次的数字比阶段 5 的报告高 15–35%，所以做了一次对照：

- 把阶段 5 的代码（`211ec0c`）与当前代码在同一时段交替各跑两次（ABAB），结果在 `reports/stage7/benchmark-ab.json`。
- 两份代码的数字交替重叠，例如冷进程 `new-game` 的 P95 依次是 105.3 / 113.3 / 102.6 / 105.9 ms。
- 同一份代码两轮之间的波动反而更大：阶段 5 代码的进程内开局，两轮分别是 10.1 ms 和 16.3 ms。
- 结论：差距来自机器当时的状态，不是代码。这里报告的是正式那一次，不是最好的一次。

- 不随局长变慢：见第 4 节，比值 1.03 / 0.95，门槛 1.5。
- 测试耗时：
  - core 13.1 s（门槛 60 s）；
  - core + content + integration 共 55.4 s（门槛 3 分钟）；
  - 加上 e2e 工具的测试（重跑时 32 个，3.9 s），仍在门槛内。
- §5 体积：
  - 简要 ≤ 6 KB、完整 ≤ 20 KB，两条模拟里都成立；
  - 第 300 回合简要上下文不超过第 10 回合的 1.5 倍；
  - 第 10、100、300 回合的快照体积在模拟输出的 `sizes` 里；
  - `SKILL.md` 16 162 字节。
- 没做到的两处：
  - Linux 上的冷进程数字（P2）；
  - §5 的调用次数表：要在端到端记录里统计，普通回合平均 ≤ 1.2（P1、P5）。机器检查已经会按剧本标注逐轮核对预算，并算出平均值。
