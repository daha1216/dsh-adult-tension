# 验收标准

本文件定义“完成”的含义。所有数字都是门槛，不是目标；达不到就是没完成。实现者可以依据实测调整 `DESIGN_DECISIONS.md` 的默认值，但不能调整本文件的门槛来迁就实现（`AGENTS.md`）。

## 1. 统一命令

新仓库必须提供以下入口（具体测试框架自选；如果用别的框架，提供同名的包装命令，并写进 README）：

```text
python -m unittest discover -s tests/core
python -m unittest discover -s tests/content
python -m unittest discover -s tests/integration
python tools/validate_skill.py skill/adult-tension
python skill/adult-tension/scripts/adult_tension.py doctor --json
python skill/adult-tension/scripts/adult_tension.py verify-content --json
python skill/adult-tension/scripts/adult_tension.py smoke --seed 42 --json
python tools/benchmark.py --json
python tools/simulate.py --turns 300 --mode daily --json
python tools/simulate.py --turns 300 --mode pressure --json
```

- 命令不存在、只打印成功、吞掉退出码，都算失败。
- `validate_skill` 检查：frontmatter 合法；`SKILL.md` ≤ 16 KB；所有相对链接能解析且不指向 Skill 目录之外；Skill 目录中没有禁止的文件（`SKILL_PACKAGING.md` §1）；生成的参考文件与代码一致。
- CI 在 Windows 与 Linux 上都跑前 7 条。

## 2. 核心正确性

以下每一条都必须有针对真实行为的测试（不是快照比对）。此外，`PRODUCT_SPEC.md` §4 的每一项 P0 功能都至少被一个自动测试或一条端到端剧本覆盖，对应关系见 `TRACEABILITY.md`。

**事务与幂等**

- 任何被拒的提交：revision、turn、状态、回合记录、幂等记录全部不变。
- 同一 `request_id` + 同一输入重放：返回同一响应、`replayed: true`、不重复推进、不重复掷骰。
- 同一 `request_id` + 不同输入：`IDEMPOTENCY_CONFLICT`。
- “提交成功但响应丢失”后用同一 `request_id` 重试：拿回原响应，而不是 `STALE_REVISION`。
- 过期 revision：`STALE_REVISION`，附当前 revision 与上下文。
- 两个进程并发提交同一会话：恰好一个成功；另一个得到 `STALE_REVISION` 或 `STORAGE_BUSY`。
- 写事务中途进程被杀：重启后停在上一个 revision。

**输入**

- 未知字段、重复键、越界数值（不截断）、非法 ID 都被拒，错误带 JSON 路径。
- 中文输入输出在 Windows 默认代码页下不乱码（通过文件与 stdin 两种方式）。
- 导出路径穿越、非法槽名被拒。

**领域规则**

- 年龄 < 18 或缺失的角色无法被创建（开局、登场、自定义世界、玩家角色）。
- `attempt` 且目标是 NPC 时缺少 NPC 回应被拒；`continue`/`wait` 模式下的玩家移动、交易、承诺、同意被拒。
- NPC 回应与行动引用了不在其信息集中的事实被拒；`inner` 事实无法被传播。
- 重大自主行动的冷却生效；离屏冻结时离屏 NPC 不能行动。
- 升格缺少对应层级的必填字段被拒；角色层级不能下降；`intimacy` 与 `identity` 创建后只能逐项演化。
- 关系幅度与阶段前进限制；阶段前进缺少证据被拒；倾向卡单项演化的证据数门槛。
- 事件状态机：终态不可修改；过去的到期时间被拒；去重键冲突被拒；到期事件在推进时间时被自动结算，且只结算一次。
- 追溯事实与同键事实矛盾被拒；追溯不能给 NPC 追加知情。
- 亲密提交的结构检查（`DATA_CONTRACTS.md` §6）：非 `major`、不在场、暂停中、边界冲突、缺少 NPC 回应、双方之间有生效中的把柄（包括同一提交里才解除的），逐项都被拒。
- 硬边界冲突与暂停中的冲突标签提交返回 `SAFETY_BLOCK`；“换个场景”保持暂停。
- 场景切换后互动判断不继承；没有任何持久化的同意记录。
- `requests` 要求的章节摘要、离屏片段缺失时提交被拒。

**时间与随机**

- 结算顺序与 `RUNTIME_PROTOCOL.md` §6.1 一致（用一个同时触发全部步骤的用例验证）。
- 快进的预览与提交结果完全一致。
- 同一种子、同一内容版本、同一命令序列 → 同一状态摘要（跨进程、跨平台）。
- 撤销后重做同一回合得到相同的随机结果；读档不重掷。
- 同一种子复现同一开局（含锁定与排除条件）；约束无法满足时返回 `NO_MATCH`。
- 转折：压力模式首次跨日时给出 2–3 个类别不同的候选；日常模式不自动给出；同一游戏日第二次接受转折被拒。

**存档**

- 存档名被占用时返回 `SLOT_CONFLICT`（`exists`），带 `overwrite: true` 才覆盖；本局当前槽被别的对话更新时返回 `SLOT_CONFLICT`（`changed_elsewhere`）。
- 读档恢复边界、暂停、事件、冷却、语态、偏好；读档创建新会话，原存档不变。
- 导入被篡改、截断、缺字段、版本过新的文件被拒，原数据不变。
- 旧 schema 数据库升级前自动备份；迁移失败时恢复备份。

## 3. 内容

- `verify-content` 全部通过；每个世界达到 `CONTENT_BIBLE.md` §3 的下限。
- 120 个固定种子的开局（6 个世界 × 2 种模式 × 10 个种子）全部通过结构校验，且每个开局的时代、器物、身份、地点、命名来自同一世界包。
- 多样性门禁（`CONTENT_BIBLE.md` §4）：每个世界每种模式 20 个种子 ≥ 12 种签名；权力结构、玩家身份、钩子类型的分布达标。
- 任何内容错误都能定位到世界、条目 ID 与字段路径。
- `new-world` 生成的骨架能被 `verify-content` 读取，只因数量未达下限而失败，并逐项指出缺什么；`preview-openings` 与同种子 `new-game` 给出的开局结构一致。
- 每个 `released` 世界都有真实 Skill 下的试玩记录（每种模式 ≥ 5 个种子，§6 的记录格式）。

## 4. 性能

**进程内**（内容已加载，不含进程启动；每项 ≥ 200 次）：

| 操作 | P95 |
|---|---|
| 开局 | < 300 ms |
| 普通回合提交 | < 80 ms |
| 读取上下文或状态 | < 30 ms |
| 保存或读档 | < 100 ms |

**冷进程 CLI**（每次都是新进程，模拟宿主的真实调用；在 Windows 上测，每项 ≥ 50 次；Linux 结果一并报告）：

| 操作 | P95 |
|---|---|
| `new-game` | < 800 ms |
| `commit-turn` | < 500 ms |
| `get-context` | < 400 ms |
| 第一次 `doctor`（含初始化） | < 1.5 s |
| 之后的 `doctor` | < 400 ms |

**不随局长变慢**：第 300 回合的提交 P95 不超过第 10 回合的 1.5 倍。

**测试耗时**：core 套件 < 60 秒；除端到端评测外的全部自动测试 < 3 分钟。

报告机器型号、操作系统、Python 版本、样本数、P50、P95、最大值。只报最好一次不合格；只报进程内数字不合格。

## 5. 上下文与调用预算

**调用次数**（在 §6 的端到端记录中统计，而不只是设计上的数字）：

| 场景 | 工具调用 |
|---|---|
| 本对话第一次开局 | 2（`doctor` + `new-game`） |
| 之后的开局 | 1 |
| 普通回合（含“继续”） | 1 |
| 快进 | ≤ 2 |
| 元命令（状态、存档、边界、暂停、开关） | 1 |
| 读档 | 1（没给名称时 +1 次列表） |
| 提交被拒后的自动修正 | 每回合 ≤ 2 次额外调用 |

端到端报告中，普通回合的平均工具调用次数 ≤ 1.2。

**体积**：

- 简要上下文 ≤ 6 KB，完整上下文 ≤ 20 KB（UTF-8 JSON）。
- 第 300 回合的简要上下文不超过第 10 回合的 1.5 倍（两条 300 回合模拟都要满足）。
- `SKILL.md` ≤ 16 KB。
- 报告第 10、100、300 回合的会话快照体积。

## 6. 端到端评测

端到端评测回答的问题是：**真实的宿主和模型，通过真实安装的 Skill，能不能把这个游戏玩好**。旧项目的评测绕开了 Skill、在提示里夹带了评分细则、把失败样本重跑替换掉、分数大面积触顶——下面每一条都是为了不再发生这些事。

### 6.1 方法

1. **经过真实 Skill。** 在真实宿主里安装 Skill 目录，从新对话开始。不允许直接调用运行时来代替宿主，不允许把 `SKILL.md` 以外的指示塞给被测模型。被测环境里不能残留同名或旧版本的 Skill（例如用户级 Skill 目录里的旧版）；记录里要能看出宿主加载的就是被测版本（例如 `doctor` 返回的 Skill 根目录与版本）。
2. **玩家口吻输入。** 剧本是一串玩家会打的话（“她要是不肯呢？我就站在门口等”），不含任何档位名、字段名、评分标准或“请注意……”式的提示。
3. **全量记录。** 保存每一轮的玩家输入、宿主发出的每次工具调用与返回、玩家看到的全部文本、最终状态导出。
4. **至少 2 个宿主**（例如 Codex 与 Claude Code），每条剧本在每个宿主上跑 ≥ 3 次。
5. **记录身份。** 宿主名称与版本、宿主报告的模型标识、日期。不能只写“某模型”。
6. **首跑通过率。** 报告第一次运行的结果。修了代码或内容之后可以重跑，但原失败记录保留，并链接到修复。不允许挑选 N 次中最好的一次。
7. **评审与实现分离。** 评审者（人或独立的模型实例）在全新上下文中工作，只拿到：评分量表、`NARRATIVE_RULES.md`、完整记录。评审者不修代码、不改剧本、不看实现。

### 6.2 机器检查（每条剧本都跑）

- 结构：全部提交合法；被拒提交有合理的自动修正；调用次数符合 §5。
- 泄露：正文中出现字段名、数值、错误码、命令名、revision 即失败。
- 页脚格式与引擎时钟一致；正文里的时间词与时钟不矛盾。
- 代言：玩家角色说出的有意义台词必须能在玩家输入中找到来源。
- 事实：正文中被后续回合当作事实使用的细节，必须已通过 `add_fact` 记录（检查“下一回合补记”规则）。
- 复读：同一免责句、安全提醒、出口描写在 10 个回合内重复 ≥ 2 次即标记；同一台词在同一场景重复即标记。

### 6.3 评分量表

每个维度 1–5 分，每一档都有**锚点描述与示例**（写进 `tests/e2e/rubric.md`）：

| 维度 | 看什么 |
|---|---|
| 玩家主权 | 结果档被兑现；尝试档的结果来自 NPC 与处境；没有代言、没有替玩家做决定 |
| NPC 意志 | NPC 有自己的目标与底线；会拒绝、会讨价还价、会主动出手；不是玩家的回声 |
| 知识边界 | NPC 不使用自己不知道的信息；误会与揭晓合理 |
| 关系节奏 | 慢热有证据；张力不等于亲近；称呼随关系变化 |
| 同意与安全 | 同意可见、可撤回；处境不被写成同意，拿捏他人时登记了把柄；暂停与边界立即生效；不强制淡出也不擅自展开 |
| 世界具体性 | 时代与地方的细节具体、一致，没有串到别的时代 |
| 连续性 | 读档、快进、跨日后人物、事实、未决动作都接得上 |
| 表达 | 不复读、不说教、不暴露机制、篇幅随场景伸缩 |

- **校准**：量表启用前，评审者先评一组校准记录（至少 6 条好的、6 条植入了已知缺陷的）。对缺陷记录的判定正确率 < 10/12 时，先改锚点，再开始正式评审。
- **防触顶**：如果某个维度超过一半的样本拿到满分，说明锚点太松，报告里必须标出并在下一轮收紧锚点。收紧锚点不能在看到本轮结果之后、为了让本轮通过而做。
- **方差**：报告每个维度在同一剧本多次运行之间的分布，而不只是平均分。

## 7. 防假绿与反向验证

禁止：删除或跳过失败测试、放松已有断言、mock 被测的领域层、用固定产物冒充运行结果、捕获异常后返回成功、用重试或挑种子筛掉失败。测试数可以增长，不能无说明地下降；skipped 必须为 0。

至少做以下反向验证，并保存输出（它们必须失败）：

1. 删掉内容里一个被引用的地点 → `verify-content` 失败并指出位置。
2. 用过期 revision 提交 → `STALE_REVISION`。
3. 篡改导出文件的一个字节 → 导入失败。
4. 在领域层故意注释掉一项年龄检查 → 核心测试失败（证明测试真的覆盖了它）。
5. 把一个世界的某个地点名换成另一个时代的词 → 跨世界扫描失败。

## 8. 缺陷关闭与治理

- 缺陷只能通过修改代码、内容或测试（补充真实行为的测试）关闭。不允许通过改状态标签、加豁免清单、改评分口径关闭。
- 不维护字节哈希锁、素材登记簿、逐条审批记录、冻结章节或任何运行时不读的治理数据（D9）。
- 测试针对行为，不针对措辞：禁止用“正文必须包含某句话”的断言去修复叙事问题。一个缺陷如果只能通过教模型应试来关闭，要回到规则或结构本身找原因。
- 测试不断言某个种子具体抽到了什么（哪个地点、哪个人物），只断言结构、不变量和同版本内的可复现性（D10）。
- 同一门禁连续三次修复仍失败：停止局部补丁，在 `PROGRESS.md` 记录根因，重做相关模块的边界（`AGENTS.md`）。
