# 设计决定

本文件分三部分：**已拍板的决定**（改动需要用户同意）、**默认值**（实现者可以依据实测调整，但必须在 `PROGRESS.md` 记录新值和理由）、**刻意留白**（完全由实现者决定）。

其他文档里单独出现的“D 加数字”（如 D8）都指本文件第一节的同号决定。

## 一、已拍板的决定

### D1 仓库里有一个自包含的 Skill 目录

可安装物是仓库中的一个目录（建议 `skill/adult-tension/`），只含 `SKILL.md`、`agents/`、`references/`、`scripts/`、运行时代码和编译后的内容。测试、开发工具、内容源文件、报告都在该目录之外。

**理由**：旧项目把 5 MB 维护数据随包分发。“仓库即 Skill”和“维护数据不进包”是冲突的，用子目录解决。

### D2 运行时只用 Python 标准库，最低 Python 3.10

运行时不依赖任何第三方包。开发工具（lint、类型检查、测试框架）可以有依赖，但不能被运行时 import。

**理由**：安装零步骤；宿主环境差异大。3.10 覆盖主流发行版和 Windows 商店版本。

### D3 SQLite 是唯一的状态存储

每个会话的状态、回合记录、幂等记录都在 SQLite 中，一次提交就是一个事务。导出格式是 JSON，只用于交换，不作为存储。

**理由**：旧项目的 YAML 文件、字节令牌、手工复制存档都源于没有事务存储。

### D4 状态只有一个写入口

所有改变状态的操作都经过同一个应用服务入口：校验 → 在事务中应用 → 递增 revision → 记录幂等结果。其他代码只读。

### D5 模型提交操作，不提交状态

模型提交的是一个小而强类型的操作列表（`DATA_CONTRACTS.md` §6），引擎负责计算时间、到期、冷却、概率、关系范围、知识约束。模型永远不直接写状态字段。

**理由**：旧项目让模型手写补丁、手算状态，事实矛盾和状态回退都源于此。

### D6 一次回合一次工具调用

`commit-turn` 在同一次调用中返回下一回合所需的上下文。上下文深度由引擎决定，模型不需要判断“该读多少”。

**理由**：感知延迟主要来自 LLM 与工具之间的往返次数和上下文长度，不是 Python 的几毫秒。

### D7 内容与引擎分离，世界包是整体

世界包是数据。所有随机组合只在同一世界包内发生，不跨包拼接不同时代的地点、人物和物件。会话开始时对所用内容做快照，之后内容更新不会改变进行中的局。

**理由**：旧项目的多轴独立抽取造成大量时代错配和“名词堆砌”式开局。

### D8 每条规则只有一个权威位置

- 行为语义：`NARRATIVE_RULES.md`（发布后为 `references/narrative.md`）。
- 结构校验：代码中的校验器。
- 世界内容：世界包数据。

文档不复述代码里的数字；代码不硬编码世界内容；`SKILL.md` 只放触发条件、调用流程和最要紧的几条规则。

### D9 不做字节哈希锁，不维护运行时不读的数据

- 禁止内容指纹锁、冻结章节哈希、依赖文件哈希、目录树快照测试、跨文档计数同步测试。
- 需要保证不变的东西，用行为断言测试。
- 运行时不读、也不改变玩家可见行为的“治理数据”一律不建。
- 缺陷只能通过修改内容或代码来关闭，不能通过修改标签、状态或豁免清单来关闭。
- 评估证据过期只会触发重新评估，永远不能成为不修复缺陷的理由。

**理由**：旧项目的登记簿、指纹和证据新鲜度约束最终阻止了修复本身。

### D10 确定性随机与算法版本

- 所有随机都由引擎产生，按“会话种子 + 用途 + 回合 + 对象”派生，使用版本稳定的算法（例如基于 `hashlib` 的派生），并记录算法版本号。
- 不依赖 `random` 模块在不同 Python 版本间的行为。
- 同一内容版本 + 同一算法版本 + 同一种子 → 同一开局。
- 跨内容版本或算法版本不承诺同一种子给出同一开局。改内容之后某个种子的开局变了，是正常的，不是回归。

**理由**：旧项目把历史种子的输出当成硬约束，文档改动也要求固定种子的输出逐字节不变，一次词汇清理因此被回退。

### D11 不兼容旧项目

不读取旧存档、不识别旧字段、不支持旧命令。新项目自己的格式从第一天起就带版本号并支持迁移。

### D12 错误可修复

每个错误都有稳定的错误码、人能读懂的说明、出错的 JSON 路径，以及可行时的修复提示。一次校验收集全部错误，不只报第一个。未知字段一律报错。

### D13 关系是三条线，不是单一好感度

信任（数值）、亲近进程（阶段历史）、张力（数值），见 `NARRATIVE_RULES.md` §6。亲近进程是历史，不是许可。

**理由**：只有信任一个数，“慢热的张力”就无处表达；单一好感度又会被当作许可。

### D14 正文不入库

引擎不保存模型写出的完整正文。每回合保存：模型提交的一句话摘要、最多 3 条对后续有用的原话摘录（每条 ≤ 80 字）、全部结构化变化。

**理由**：保存正文需要第二次调用或更大的请求；续写需要的是事实和语气锚点，不是全文。

### D15 性别与配对可配置

不硬编码玩家或 NPC 的性别与取向。玩家的设定和 NPC 性别构成偏好保存在会话里；世界包提供默认分布。

内容文本中凡是指代可变性别角色的地方，一律用模板占位（例如 `{npc.ta}`、`{npc.称呼}`），由引擎按实际性别渲染。校验器拒绝在可变性别槽位的文本中出现写死的“他/她”。

### D16 内容只有两层：世界包，与极薄的通用结构层

每个世界包自成整体，它的地点、人物、活动、压力、转折都带着自己的时代感（D7）。跨世界共享的只有一个**通用结构层**：

- 允许放进通用层的：结构模板（五拍压力的骨架、关系阶段表、转折类别表、权力结构类型、NPC 回应光谱的描述）、内容标签表、命名规则。
- 不允许放进通用层的：任何带时代、地域、器物、职业、称谓的文本。通用层中的每一个字符串都要通过跨世界词表扫描（`CONTENT_BIBLE.md` §6）。
- 多个世界共享同一时代底色时（例如两个民国世界），可以写一个**时代底包**，世界包用 `extends` 引用它。继承在编译期展开，运行时只看到完整的世界包；底包本身不能被选为世界。

**理由**：旧项目最严重的内容问题是全局池里的题材条目串进其他时代、整数下标错绑、批量生成的同形框架。只允许“结构共享、文本不共享”，才能在扩到 20 个世界时不重新制造这些问题。

## 二、默认值

实现者可以依据实测调整，但必须在 `PROGRESS.md` 记录新值和理由。

| 项 | 默认值 |
|---|---|
| NPC 重大自主行动冷却 | 每 NPC 每 3 个玩家回合 1 次 |
| 离屏推演分档 | 1–15 分钟：常规；16–59 分钟：简短推演；≥ 60 分钟或跨日：完整推演 |
| 离屏片段触发 | 玩家“继续”且至少一个重要 NPC 不在场、且该 NPC 不在冷却中 |
| 单次提交信任变化 | ≤ 2 |
| 单次提交亲近进程 | 最多前进 1 个阶段 |
| 倾向卡单项演化 | 同方向 ≥ 2 条不同回合的证据；界线项放宽 ≥ 3 条 |
| 中期转折 | 压力模式首次跨日提供；每局自动提供 1 次，玩家主动要求不限次数但同一游戏日最多 1 次 |
| 上下文深度 | 简要；以下情况给完整上下文：开局、读档、每 5 回合、地点变化、新角色登场、跨日、上一次提交出错 |
| 上下文体积 | 简要 ≤ 6 KB；完整 ≤ 20 KB（UTF-8 JSON） |
| 章节摘要 | 每 20 回合或每次跨日，引擎要求模型在下一次提交中附章节摘要（≤ 300 字）；摘要之前的回合记录归档 |
| 章节上限 | 10 章；超出时要求把最早几章合并为一段“前情” |
| 无 `advance_time` 的提交 | 时钟默认推进 3 分钟 |
| 单次时间推进上限 | 30 天 |
| 模型自动修正提交 | 同一回合最多 2 次，之后向玩家说明并停下 |
| 近期去重 | 本机最近 10 局的开局签名 |
| 幂等记录保留 | 每个会话最近 1000 条 |
| 撤销深度 | 回退到本次读档或开局为止 |
| 开局正文 | 约 300–700 字 |
| `SKILL.md` 体积 | ≤ 16 KB（UTF-8） |

## 三、刻意留白

以下完全由实现者决定，只要满足公开合同：

- 包管理器、测试框架、lint 与类型检查工具、CI 平台。
- 内部模块划分、类名、函数名（`ARCHITECTURE.md` 的目录树只是建议）。
- SQLite 表结构、索引、是否分库。
- 内容源文件的编写格式（可以是 JSON、TOML 或其他，只要编译产物是运行时可读的 JSON 且运行时只用标准库）。
- 日志格式与位置（不得写进用户存档目录之外的意外位置）。
- 确定性随机的具体派生算法（满足 D10 即可）。
- 事实键、事件去重键的具体构造方式。
- 上下文 JSON 的内部字段命名（满足 `DATA_CONTRACTS.md` 的语义和体积上限即可）。
- 性能优化手段（预编译内容、懒加载、缓存）。

发现更简单的设计可以替换任何建议结构，在 `PROGRESS.md` 说明理由即可。不得为了降低工作量而改变玩家体验、数据语义、验收数字或来源边界。
