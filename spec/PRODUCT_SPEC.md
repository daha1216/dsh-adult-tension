# 产品规格

## 1. 产品定义

Adult Tension 是面向 Codex、Claude Code 等 AI 宿主的中文成年人互动叙事 Skill。用户一句“开局”，就进入一个有生活质感、有人物意志、会自己运转的世界。玩家扮演其中一个成年人，与多名成年 NPC 在日常、职业、利益、欲望与秘密之间形成关系张力，并看到后果不断累积。

分工：

- **宿主模型**负责理解玩家意图、决定 NPC 如何回应、写叙事正文。
- **引擎**负责状态、时间、规则校验、确定性随机、事件到期、存档，以及每回合给模型最小而足够的上下文。

模型写故事，引擎守事实。模型不需要记规则细节；规则违反由引擎拒绝并给出可修复的错误。

## 2. 目标用户与使用方式

- 在 AI 宿主里用中文玩文字互动叙事的成年用户。
- 主要输入是自然语言；控制类操作用短命令。
- 单局可能持续数百回合、跨多个对话；用户会存档、读档、隔天续玩。
- 用户在意：开局第一屏的质感、NPC 像真人、自己的行动不被模型篡改、慢热的张力、回应快、存档可靠。

## 3. 体验原则

1. **第一屏就有具体生活。** 开局给出具体地点、时间、人物、正在发生的事和一个可行动的钩子，不堆设定名词。
2. **玩家主权。** 玩家怎么说，就怎么执行到对应程度（见 `NARRATIVE_RULES.md` §1）；模型不替玩家做决定、不替玩家说话、不移动玩家。
3. **NPC 是人，不是道具。** NPC 有目标、顾虑、代价和自己知道的事；可以拒绝、协商、讨价还价、表面配合，也可以主动出手，但不能无理由围着玩家转。
4. **慢热优先。** 关系和张力靠证据一步步累积，任何一次转变都要说得出原因。
5. **世界会自己动。** 时间推进时，不在场的人也在生活；承诺会到期，风声会传开，局势会转折。
6. **后果可追踪。** 关系变化、承诺、秘密、风险都有记录和原因，能在状态里看到。
7. **成年人自主与边界。** 所有角色是明确成年人；同意随时可以撤回；硬边界和暂停由引擎强制执行。
8. **快。** 一个普通回合只调用一次工具；上下文不随局长膨胀。
9. **可靠。** 存档不丢、不串、重试不重复推进；升级不毁存档。

## 4. 功能清单

分级：**P0** 首个正式发布必须完成；**P1** 发布后第一个迭代；**P2** 远期方向，不得为它提前做复杂设计。

### 4.1 开局

| 功能 | 级别 | 说明 |
|---|---|---|
| 随机开局 | P0 | 从已发布世界中选世界、地点、人物组合、活动与钩子，组合只在同一世界包内发生 |
| 日常 / 压力两种模式 | P0 | 用户没指定时，先用一句话问“1 日常 / 2 有压力”；回答 1、2 或模式名均可；只有明确说“随便”才随机；读档永远不问 |
| 日常模式语义 | P0 | 没有外部压力、没有倒计时、没有到期事件；张力来自人物本身与生活细节 |
| 压力模式语义 | P0 | 开局即带三层事件：立即（本场景内）、近期（当天或次日到期）、远期（伏笔，数日后）；首次跨日提供中期转折 |
| 指定锁定 | P0 | 可锁定世界、地点、人物组合、活动、压力、钩子中的任意几项，其余随机 |
| 否定约束 | P0 | “不要职场”“别是港口”之类转成排除条件；无法满足时如实告知，不假装已满足 |
| 包外题材 | P0 | 指定的时代或地点不在任何世界包内（如“盛唐长安”）时，说明没有现成世界，并提供两个选项：最接近的现有世界，或自定义世界 |
| 自定义世界 | P0 | 用户描述一个世界，模型写出一个小型世界包草稿，引擎用同一校验器（较低最低数量）验证后开局；只存在于本局，不进入全局内容 |
| 玩家角色设定 | P0 | 可指定玩家的性别、年龄段、职业/身份、称谓；不指定则由世界的玩家身份池生成，不能总是同一种默认人设；局中可以改称谓与姓名，用最小因果桥接入 |
| 配对偏好 | P0 | 可指定希望出现的 NPC 性别构成（如“女性 NPC 为主”“男性”“不限”）；偏好保存在会话里，影响开局与后续新登场角色；没有指定时按世界包的默认分布 |
| 权力结构多样 | P0 | 人物组合覆盖玩家高位、NPC 高位、平等、可切换四类权力结构，随机开局不能长期偏向一类 |
| 开局收尾 | P0 | 正文结尾停在一个未决、可接的动作上，优先是非交易性的靠近（递东西、让座、同路），而不是摊牌式的交易 |
| 已有进行中的局 | P0 | 当前会话有未存档的进度时，再“开局”先确认：存档后开局 / 直接开局 / 取消 |
| 种子复现 | P0 | 每个开局显示种子编号；“重开 N 号”在同一内容版本下复现同一开局 |
| 近期去重 | P0 | 未指定种子时，避开本机最近若干局的相同开局签名 |
| 开局预览 | P2 | 先给三个一句话开局，让用户挑 |

### 4.2 回合与主权

| 功能 | 级别 | 说明 |
|---|---|---|
| 自然语言行动 | P0 | 玩家直接描述行动、对白、意图 |
| 结果档 / 尝试档 / 改写档 | P0 | 见 `NARRATIVE_RULES.md` §1；引擎要求每次提交声明行动模式 |
| 继续 / 等待 | P0 | 空输入、“继续”、“……”、“你决定”等推进场景，至少产生一个可观察的变化，玩家角色不做重大决定；时钟不能连续多回合原地不动 |
| 撤销 | P0 | “撤销”或“刚才不算”回到上一回合 |
| 改写上一回合 | P0 | “刚才不算，改成 Y”原子地撤销并以 Y 重新执行 |
| 追溯设定 | P0 | “其实……”补充一条过去就成立的事实，不能与已记录事实矛盾、不能替 NPC 追加同意 |
| 快进 | P0 | “快进到晚上/明早/三天后”；引擎按跨度推演离屏世界 |
| 场景跳转 | P0 | 玩家移动到另一地点，引擎记录地点与在场人员变化 |

### 4.3 世界与人物

| 功能 | 级别 | 说明 |
|---|---|---|
| NPC 决策卡 | P0 | 目标、所知、顾虑、压力反应、对玩家的态度与原因 |
| 知识边界 | P0 | 事实记录“谁知道”；NPC 只能依据自己知道的事实行动 |
| NPC 回应光谱 | P0 | 拒绝 / 协商 / 有限配合 / 表面配合 / 真诚配合，按角色与处境选择 |
| NPC 自主行动与冷却 | P0 | NPC 可以主动出手；重大自主行动有冷却 |
| 关系与张力 | P0 | 信任、亲近进程、张力三条线，每次变化带原因 |
| 亲密偏好与演化 | P0 | 每个重要 NPC 有私密倾向卡；只能靠多次证据逐项演化 |
| 身份与处境 | P0 | 每个重要 NPC 有资源、限制、暴露风险；处境给出压力和有代价的出路，处境永远不等于同意 |
| 新角色登场与升格 | P0 | 背景人物可以被升格为重要 NPC，补齐决策卡 |
| 离屏推演 | P0 | 按时间跨度分档推演不在场角色；可冻结 |
| 离屏片段 | P0 | 玩家“继续”而某个重要 NPC 不在场时，可以插入一段简短的离屏片段 |
| 事件与承诺 | P0 | 约定、截止、风声、机会有生命周期，到期由引擎判定 |
| 概率事件 | P0 | 由引擎确定性掷骰，模型不得自己决定结果 |
| 关系传播 | P0 | 消息沿人际渠道传播，可能走样 |
| 中期转折 | P0 | 压力模式在首次跨日时提供一次转折，七类方向（信息、人事、资源、制度、时限、关系、意外）中给 2–3 个候选；玩家也可以随时说“来点转折”主动要求 |
| 信息差与误信 | P0 | 事实可以只被部分人知道，也可以被某些人错误地相信；误会戏有结构化基础 |
| 章节摘要与长期记忆 | P0 | 引擎按需要求模型写章节摘要，旧回合压缩为摘要，关键事实永久保留 |

### 4.4 呈现

| 功能 | 级别 | 说明 |
|---|---|---|
| 固定输出格式 | P0 | 见 `NARRATIVE_RULES.md` §9 |
| 状态 | P0 | 六行人话：① 时间·地点 ② 在场的人与各自状态 ③ 关系（人话，不露数值） ④ 压力与待办 ⑤ 边界与暂停 ⑥ 现在可以做什么 |
| 状态+ | P0 | 展开关系变化原因、承诺与期限、玩家角色已知的秘密、人物卡摘要、谁能主动出手；仍然不暴露字段名 |
| 调试 | P0 | 结构化状态、最近提交、上下文体积、校验信息 |
| 表层/里层语态 | P0 | 每个 NPC 可切换，优先级见 `NARRATIVE_RULES.md` §4 |
| 内心可见 | P0 | 开关；开启后正文可写 NPC 内心，但内心永远不进入任何角色的知识 |
| 离屏推演开关 | P0 | 关闭即冻结离屏世界 |
| 叙事助手 | P0 | 开关；开启后每回合末尾给 2–3 个可选行动提示，不替玩家决定 |
| 人称 | P0 | 默认第二人称称呼玩家角色（“你”），NPC 用第三人称；世界包可以声明别的默认值 |
| 风格偏好 | P1 | 节奏（慢热/标准/直接）与尺度（含蓄/标准/直白），只影响写法，不影响规则 |

### 4.5 安全

| 功能 | 级别 | 说明 |
|---|---|---|
| 成年人断言 | P0 | 每个角色的年龄明确 ≥18，正文不得出现未成年暗示 |
| 硬边界 | P0 | “边界：不要 X”登记后，引擎拒绝任何带冲突内容标签的提交 |
| 暂停 / 安全词 | P0 | “暂停”立即停止当前亲密或冲突场景，回到中性叙述，直到玩家恢复 |
| 同意可撤回 | P0 | NPC 或玩家角色任何时候撤回同意，场景立即停下 |
| 处境不是同意 | P0 | 一方握有另一方的把柄、债务或生计时，双方之间不能进入亲密场景，直到把柄解除；把柄由引擎记录 |

### 4.6 存档与会话

| 功能 | 级别 | 说明 |
|---|---|---|
| 自动保存 | P0 | 每次成功提交即持久化 |
| 命名存档 | P0 | “存档 名称”；名称可以是中文，空格转为短横线；同名覆盖须确认；回执“已保存到「名称」·第 N 回合” |
| 快速存档 | P0 | “s/qs/快速存档”存到当前槽（本局最近一次保存或读取的槽；没有则自动命名） |
| 冲突处理 | P0 | 同一存档被另一个对话改动过时，给三个选项：A 读取最新 / B 另存为新名 / C 取消 |
| 另存为 | P0 | 回执“已另存为「名称」·第 N 回合” |
| 读档 | P0 | “读档 名称”；读档不重掷任何随机，边界、暂停、事件、冷却原样恢复；从未决动作的前一刻续写，不重复开局三段 |
| 存档列表 | P0 | 名称、世界、回合、游戏内时间、最后游玩时间 |
| 续玩 | P0 | 新对话里说“继续上次/恢复”，列出最近会话并续上 |
| 导出 / 导入 | P0 | 导出为文件并返回路径；导入接受文件路径或粘贴的 JSON |
| 删除存档 | P1 | 需要确认 |
| 版本迁移 | P0 | 未来内容或存档格式升级时，旧存档先备份再迁移 |

## 5. 命令与别名

所有命令都可以用自然语言表达；以下为必须识别的短形式。完整表写入 `SKILL_TEMPLATE.md`。

| 意图 | 形式 |
|---|---|
| 开局 | 开局、新游戏、开局 日常、开局 压力、开局 港口、重开 N 号、自定义世界 …… |
| 转折 | 来点转折 |
| 世界列表 | 世界列表、有哪些世界 |
| 继续 | 继续、c、……、空输入 |
| 撤销 / 改写 | 撤销、刚才不算、刚才不算，改成 Y |
| 追溯 | 其实…… |
| 快进 | 快进到……、跳到…… |
| 状态 | 状态、状态+、调试 |
| 存档 | 存档 [名称]、s、快速存档、qs、另存为 名称 |
| 读档 | 读档 [名称]、l、存档列表 |
| 恢复 | 恢复（有歧义时三选一：恢复上次会话 / 读取某存档 / 恢复被暂停的场景） |
| 导出 / 导入 | 导出存档、导入存档 |
| 设定 | 边界：……、撤销边界 ……、暂停（安全词、pause）、内心可见 开/关、语态 某人 表/里（“别装了”“说点真心话”等自然说法亦可）、离屏推演 开/关（冻结世界）、叙事助手 开/关 |
| 帮助 | 帮助、h、? |

缺少必要对象时，追问一次，不猜测。例：“存档”没有名称时，用当前世界与回合生成默认名并在回执里告知；“读档”没有名称时，列出存档；“语态 里”没有指定人物且在场只有一个重要 NPC 时，默认是那个人，否则追问。

## 6. 非目标

- 不做图形界面、网页服务或多人联机。
- 不做玩家账号或云同步。
- 不兼容旧项目的存档、字段、命令或目录。
- 不让引擎生成叙事正文；引擎只提供事实、约束和确定性结果。
- 不追求海量素材；追求每个世界的整体质量。

## 7. 成功指标

以 `ACCEPTANCE.md` 为准，要点：

- 开局：一次工具调用（首次使用两次），冷进程 CLI P95 < 800 ms；120 个种子的开局全部通过结构校验；每个世界每种模式 20 个种子至少 12 种不同签名。
- 回合：一次工具调用，冷进程 P95 < 500 ms；常规上下文 ≤ 6 KB，300 回合时不超过 10 回合时的 1.5 倍。
- 可靠：300 回合模拟零不变量违反；重复请求不重复推进；过期 revision 被拒；升级与卸载不丢存档。
- 质量：16 个端到端剧本全部通过独立评审，重点检查玩家主权、NPC 意志、知识边界、慢热、安全。
