# Adult Tension 全量重写蓝图

## 结论

在全新目录从零重写。要重写的是实现、状态模型、素材组织、维护方式和 Skill 封装；要保留的是玩法——玩家主权、有自己意志的 NPC、慢热的关系张力、会自己运转的世界、可靠的长线记忆与存档。

本目录是新实现的唯一需求入口。它用产品语言重新定义了全部必须保留的玩法，执行 Agent 不需要、也不得回看旧项目。

## 为什么重写，以及这次要避免什么

旧实现失败的根源不在某个模块，而在几种结构性问题。新蓝图针对每一种都给出了约束：

| 旧问题 | 新蓝图的对应约束 | 位置 |
|---|---|---|
| 模型手工编辑大段状态文本、补丁键过多，一个回合要读很多规则 | 模型只提交小而强类型的操作列表；时间、到期、冷却、概率、校准由引擎计算 | `DATA_CONTRACTS.md` §6、`RUNTIME_PROTOCOL.md` §6 |
| 同一规则写在文档、数据、脚本三处，互相漂移 | 规则只有一个权威位置；文档写语义，代码实现校验，数据只放内容 | `DESIGN_DECISIONS.md` D8 |
| 素材海量、跨时代拼接，开局像名词堆砌 | 每个世界包是一个整体，开场节点由作者设计、组合只在包内进行，另设开局质量评审 | `CONTENT_BIBLE.md` |
| 维护治理（来源哈希、审查镜像）与运行时耦合 | 发布物只含运行所需；审查只是源文件上的简短状态 | `CONTENT_BIBLE.md` §7 |
| 多文件、多锁、令牌协议易失配 | SQLite 单事务 + revision 乐观锁 + request_id 幂等 | `RUNTIME_PROTOCOL.md` §2 |
| 每回合读大量规则与全量状态，慢而贵 | 一次回合一次工具调用；上下文有固定体积上限，不随回合数增长；`SKILL.md` 有字数上限 | `ACCEPTANCE.md` §5 |
| 安装要复制一堆目录、依赖第三方库；5 MB 治理数据随包分发 | 自包含 Skill 目录，纯标准库，首次调用自动初始化；维护数据不进 Skill | `SKILL_PACKAGING.md` |
| 登记簿、指纹、哈希锁、冻结章节反过来阻止修复；靠改标签“闭合”缺陷 | 运行时不读的东西不维护；禁止字节哈希锁；缺陷只能靠改内容或代码关闭 | `DESIGN_DECISIONS.md` D9、`ACCEPTANCE.md` §8 |
| 实玩评估绕过 Skill、续写提示里夹带评分细则、失败样本被重跑替换、分数触顶 | 评估必须经真实 Skill 与工具调用；玩家口吻输入；报首跑通过率；锚点化量表 | `ACCEPTANCE.md` §6–§8 |
| 规则、评审、产品对描写尺度口径不一 | 尺度只在一处定义，SKILL 与评审量表都引用它 | `NARRATIVE_RULES.md` §7 |

## 交接前必须做的事

1. **旧项目副本不能出现在本目录和新仓库里。** 本目录原有的 `adult-tension/`（旧项目的完整拷贝）已于 2026-09-27 删除。以后也不要把旧项目的任何副本放进来：它与“不得读取旧项目”的边界直接冲突，执行 Agent 极易被它带偏。
2. 在**新的空仓库**里实现，不要在本目录里写代码。把本目录（不含 `REVIEW.md`）放进新仓库的 `spec/`；根目录的 `AGENTS.md` 只写一句“先读 `spec/AGENTS.md`”（`DELIVERY_PLAN.md` 阶段 0）。本目录不是可安装成品。
3. 要求执行 Agent 先读 `AGENTS.md`，并在新仓库建立 `PROGRESS.md`。

## 已拍板的方向

- 继续做面向 AI 宿主的中文成年人互动叙事 Skill，仅限虚构成年角色。
- 玩法全部保留并重新定义：随机或指定题材开局、玩家主权三档、撤销与改写、NPC 自主与冷却、知识边界、关系与张力递进、表里语态、内心可见、离屏推演与冻结、中期转折、事件与承诺、硬边界与暂停、存读档与续玩。
- 第一版只有一个统一运行时，不兼容旧存档、旧字段、旧命令。
- 内容与引擎分离，世界包只是数据；首发 6 个高质量世界，配套可重复的内容扩充流程，后续按流程扩到更多世界。
- 运行时只有一个状态写入口；读接口有多个视图。
- 仓库里有一个自包含、可直接安装的 Skill 目录（只含运行所需），开发工具、测试和报告放在它外面；用户只需要安装、加载、说“开局”。
- 首发 6 个世界 + 自定义世界兜底；按内容扩充流程逐步扩到 12、20 个世界。
