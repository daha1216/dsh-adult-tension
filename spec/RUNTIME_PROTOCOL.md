# 运行时协议

本文件定义调用 Agent 与运行时之间的交互：怎么调用、调用顺序、并发与重试、时间怎样结算、出错后怎么恢复。数据形状见 `DATA_CONTRACTS.md`，行为语义见 `NARRATIVE_RULES.md`。

## 1. 调用方式

```text
python <skill_dir>/scripts/adult_tension.py <command> --json [--input-file PATH] [--data-dir PATH]
```

- **输入**：一个 JSON 对象，来自 `--input-file` 或 stdin。按字节读取、按 UTF-8 解码（容忍 BOM）。没有必填输入的命令（`doctor`、`version`、`list-worlds`、`list-slots`、`list-sessions`）可以不给输入。
- **玩家文本永远不进命令行参数。** 引号转义与 Windows 代码页都会损坏中文。
- **输出**：stdout 只有一个 JSON 信封（`DATA_CONTRACTS.md` §1），无论控制台代码页是什么，一律以 UTF-8 字节输出。诊断日志写 stderr 或日志文件。
- **退出码**：成功为 0；失败为非 0，且仍然输出信封。不同类别的失败（输入与领域错误、环境错误、内部错误）使用稳定且不同的退出码，具体数值由实现者决定并写进 `references/`。
- **Python 发现、数据目录定位**见 `SKILL_PACKAGING.md`。

## 2. revision、幂等与并发

### 2.1 三类调用

| 类别 | 命令 | 必须带 |
|---|---|---|
| 读 | `get-context`、`status`、`list-*`、`version`、`export-save` | 无 |
| 会话内写 | `commit-turn`、`undo-turn`、`set-boundary`、`set-safety`、`set-preferences`、`save-slot`、`delete-slot` | `request_id`、`session_id`、`expected_revision` |
| 创建会话 | `new-game`、`load-slot`、`import-save` | `request_id`（此时还没有 revision 可以期待） |

### 2.2 幂等

- `request_id`：8–64 位 `[A-Za-z0-9_-]`。为了免去模型自造 ID，每个成功或失败的响应都附带一个新的 `next_request_id`，模型下一次写操作直接使用它。
- 幂等作用域：会话内写按 `(session_id, request_id)`，创建会话按数据目录全局 `request_id`。
- 只记录**成功**的写请求：保存输入的规范化摘要与完整响应。每个会话保留最近 1000 条，创建会话类保留最近 1000 条。
- 相同 `request_id` + 相同输入 → 原样返回当初的响应，并标记 `replayed: true`；不增加 revision，不推进回合，不重复掷骰。创建会话类的重试返回同一个会话。
- 相同 `request_id` + 不同输入 → `IDEMPOTENCY_CONFLICT`。
- 失败的请求不记录，状态也没有变化，修正后可以直接重交。

### 2.3 处理顺序

每个写请求严格按这个顺序处理：

1. 解析与形状校验（未知字段、重复键、类型、范围）。
2. 幂等查找；命中则直接返回旧响应。
3. revision 检查；不等则返回 `STALE_REVISION`，附当前 revision 和简要上下文。
4. 领域校验与应用（§5、§6）。
5. 同一事务内写入新状态、回合记录、幂等记录，revision +1。

幂等查找必须在 revision 检查之前。只有这样，“提交成功但响应丢失”后的重试才会拿回原结果，而不是被当成过期请求拒绝。

### 2.4 revision 与 turn

- 每次会话状态变化，revision +1。`save-slot` 不改变游戏状态，revision 不变。
- 只有叙事回合推进 turn：`commit-turn` 使 turn +1。开局后 turn = 1。
- 元操作（边界、暂停、偏好、存档）不推进 turn。
- `undo-turn` 使 turn 回到上一回合，revision 仍然 +1。
- 显示给玩家的“回合：N”是刚写完的那一回合的编号。

### 2.5 并发

- 同一会话可能被两个对话同时游玩。写事务获取写锁（例如 SQLite `BEGIN IMMEDIATE` 加有限的忙等待）。拿不到锁时返回 `STORAGE_BUSY`，调用方用同一个 `request_id` 重试。
- 后提交的一方会得到 `STALE_REVISION`。调用方必须基于新的上下文**重新判断**，不能只替换 revision 后重放旧操作。
- `get-context` 只读，不接受 `expected_revision`，永远返回当前 revision。

## 4. 首次使用与开局

### 4.1 调用预算

- 本对话第一次玩法操作：`doctor` → `new-game`，共 2 次调用。
- 之后的开局：`new-game`，1 次调用。
- `doctor` 成功后在数据目录记录版本标记。同一版本的后续 `doctor` 走快速路径。

### 4.2 调用前由模型完成的事

以下判断不需要调用运行时：

- 用户没说模式时，先问一句“1 日常 / 2 有压力”；只有用户明确说“随便”才随机。
- 当前对话已经有进行中的局，且上下文的 `save.turns_since_save` 大于 0（有未存档的进度）时，先确认：存档后开局 / 直接开局 / 取消。直接开局不会删除旧局，旧局仍然可以续玩。
- 用户要的题材不在任何世界包内时，说明情况，并给两个选项：最接近的现有世界，或自定义世界。需要世界列表时调用 `list-worlds`。

### 4.3 `new-game` 输入

```json
{
  "request_id": "r_0001",
  "mode": "pressure",
  "seed": null,
  "locks": {"world_id": "harbor_night_shift"},
  "excludes": {"content_tags": ["workplace_power"], "world_ids": []},
  "player": {"gender": "male", "age": null, "identity_hint": "理货员", "name": null, "title": null},
  "npc_gender_preference": "mostly_female",
  "custom_world": null,
  "preferences": {"inner_view": false, "assistant": false}
}
```

- `locks` 可以锁定世界、地点、人物组合、活动、压力、钩子中的任意几项。
- `seed` 是玩家看到的“种子”编号。编号必须足以复现开局：如果开局用了锁定或排除，编号要么编码这些条件，要么在导出时一并带上；实现者自选方案。同一内容版本下，同一编号得到同一开局。
- 约束无法同时满足时返回 `NO_MATCH`，附上最接近的可选项；模型如实告诉用户，不假装已经满足。
- `custom_world` 按 `DATA_CONTRACTS.md` §8.2 校验；失败时返回 `CONTENT_ERROR` 与字段路径，模型修正后重交。

### 4.4 引擎做的事

1. 解析约束，得到候选集。
2. 没有指定种子时生成种子。先取候选，若其开局签名（世界 + 地点 + 人物组合 + 活动或压力 + 钩子，与 `CONTENT_BIBLE.md` §4 相同）与本机最近 10 局重复，就换下一个；候选耗尽时接受重复。签名历史存放在数据目录中，不在会话里。
3. 在同一个世界包内实例化：地点、玩家身份、NPC（名字来自名字池，同局不同姓，遵守配对偏好和权力结构）、活动、钩子。压力模式还要实例化三层事件。
4. 建立初始事实与关系边（`DATA_CONTRACTS.md` §4），做内容快照，写入会话。revision = 1，turn = 1。
5. 返回完整上下文与 `opening`：世界观要点、人物要点、场景、钩子、种子编号。

模型据此写开局（格式见 `NARRATIVE_RULES.md` §9）。

### 4.5 正文里出现的新细节

正文不是记忆。模型在正文里新写出的、之后需要被继承的细节（某人口袋里的钥匙、门口停着的车），必须在下一次提交中用 `add_fact` 记录（来源标为观察），否则之后不被当作事实。开局正文也一样。

## 5. 回合循环

```text
（上一次返回的 context）
  → 模型判断：元命令？还是叙事输入（行动模式、NPC 回应、操作列表）
  → commit-turn（1 次调用）
  → 根据 applied / resolved_events / 新 context 写正文与页脚
```

- **元命令**（状态、存档、边界、暂停、开关、帮助）走对应命令，只输出回执，不写叙事，不推进回合。
- **叙事输入**：按 `NARRATIVE_RULES.md` §1–§3 组装操作。
- 每次提交必须带 `summary`（一两句，第三方视角，只写已提交的变化）和 `open_action`（结尾停住的那个未决动作，≤ 80 字）。可以附 ≤ 3 条原话摘录，每条 ≤ 80 字。
- **时钟不能原地不动**：提交里没有 `advance_time` 时，引擎按默认值推进（`DESIGN_DECISIONS.md`）。返回的时钟就是权威时间，正文里的时间词必须与之一致。
- 操作按列出的顺序应用，后面的操作看得到前面操作的效果（例如先 `introduce_character` 再 `npc_response`）。校验在工作副本上逐个进行，任何一个失败都会让整个提交失败，状态不变。
- **NPC 拒绝不是错误。** `npc_response: refuse` 是正常的叙事结果；错误只表示提交本身不合法。
- 条件请求：上下文的 `requests` 字段会要求下一次提交附带某些内容（章节摘要、离屏片段）。缺少时提交被拒，错误的 `hint` 会说明要补什么。

### 5.1 提交失败时

| 错误 | 模型怎么做 | 玩家看到什么 |
|---|---|---|
| `INVALID_INPUT`、`INVARIANT_VIOLATION`、`NOT_FOUND`（提交里引用了不存在的角色或事件） | 按 `details` 修正后重交；同一回合最多自动修正 2 次 | 什么都看不到；2 次仍失败时，用一句话说明“这一步没能记下”，并请玩家换个说法 |
| `SAFETY_BLOCK` | 换一个不冲突的写法重交 | 一句话说明原因（年龄、边界或暂停）；这是唯一需要主动告知的拒绝 |
| `STALE_REVISION` | 用错误里附带的上下文重新判断，然后重交 | 如果是另一个对话推进了这局，用一句话说明 |
| `STORAGE_BUSY`、宿主超时或无输出 | 用**同一个** `request_id` 重试，最多 3 次 | 无 |

## 6. 时间推进与结算

### 6.1 每次 `advance_time` 触发的结算顺序

1. **时钟前进。** 跨地点或跳过 ≥ 60 分钟时开启新场景编号，并清空上一场景的互动判断（`NARRATIVE_RULES.md` §7.1）。
2. **到期事件**：按 `(due, id)` 顺序处理 `due ≤ 新时钟` 的 `pending` 事件。
   - 承诺、截止到期未兑现 → `expired`。
   - 带概率的事件 → 掷骰，得到 `hit` 或 `miss`。
   - 伏笔到期 → 浮出，记为 `resolved` 并在结果里说明。
3. **状态到期**：带期限的角色状态（醉意、睡眠、受伤、外出）到期后清除。
4. **离屏推演**（开启时），按跨度分档，见 §6.2。
5. **传播**：标记为扩散中的消息沿关系边传播一跳或多跳（跳数随跨度），每跳由确定性掷骰决定是否传到。消息走样只能通过模型的 `spread_rumor` 以新事实的形式出现，引擎不改写原事实。
6. **上下文请求**：判断是否需要章节摘要、是否提供转折、离屏片段有哪些候选。

回合级的计数（冷却、离上次转折的回合数）按玩家回合计，不按分钟计，在提交末尾统一推进。

### 6.2 离屏推演分档

| 跨度 | 档位 | 引擎做什么 | 模型做什么 |
|---|---|---|---|
| 1–15 分钟 | 常规 | 只结算到期事件与状态 | 无 |
| 16–59 分钟 | 简短 | 结算，并传播一跳；列出离屏片段候选 | 可以在下一次提交里写 `offscreen_beat` |
| ≥ 60 分钟或跨日 | 完整 | 结算，并多跳传播；指定最多 3 个必须有离屏片段的重要 NPC | 同一次提交里必须为每个指定 NPC 附 `offscreen_beat` |

离屏推演关闭（冻结）时：不传播，不产生离屏片段，不在场的 NPC 不能行动，状态到期照常。到期事件照常结算，因为它们是既定期限，不是离屏推演。

`offscreen_beat` 只能记录该 NPC 自己的行动、NPC 之间的关系与事实变化，以及事件的创建与推进。它不能改变玩家角色，不能让 NPC 知道其信息集以外的事，不能兑现或取消涉及玩家的事件。

### 6.3 随机

- 所有随机结果都由引擎从会话种子派生（`DESIGN_DECISIONS.md` D10）。派生输入只用结构化坐标，例如事件 ID、回合号、本次提交中的第几次掷骰；**不包含模型写的自由文本**，免得改一下措辞就能换一次结果。
- 撤销后重做同一回合，得到同样的掷骰结果；读档不重掷。

### 6.4 快进：预览 + 提交

“快进到晚上”“三天后”是一个叙事回合（turn +1），最多 2 次调用：

1. `get-context` 带 `preview_time`，返回目标时钟、将到期的事件及其确定性结果、必须有离屏片段的 NPC（附其目标与信息集摘要）、将到期的状态。预览不改变状态。
2. 模型据此写好离屏片段，提交 `commit-turn`，内容为 `advance_time` 加各 `offscreen_beat`。提交的结算结果必须与预览一致。

没有先预览就直接提交大跨度时，如果缺少必需的离屏片段，提交被拒，错误里附带同样的预览内容，模型补齐后重交。

单次推进上限默认 30 天。

### 6.5 转折

- 压力模式首次跨日时，上下文的 `requests.twist_offer` 给出 2–3 个候选。候选来自世界包、类别不同，由确定性选取。
- 玩家说“来点转折”时，用 `get-context` 加 `want_twist: true` 取得候选。同一游戏日最多接受一次。
- 玩家选定后，下一次提交带 `twist_accept`。玩家也可以口述一个自己的转折（要有类别）。

## 7. 上下文深度与长期记忆

- 深度由引擎按 `DESIGN_DECISIONS.md` 的默认规则决定。模型觉得信息不足时，可以调用 `get-context` 并带 `depth: "full"`。
- **章节**：每 20 回合或跨日时，`requests.chapter_summary: true`，下一次提交必须附 `chapter_summary`（≤ 300 字）。章节摘要写入后：
  - 该章各回合的摘要与摘录归档，不再进入上下文；
  - 章节数超过上限（默认 10）时，引擎要求把最早几章合并成一段“前情”。
- **事实永不删除。** 上下文只选取与在场者、玩家角色已知、待办事件相关的事实，并受 `DATA_CONTRACTS.md` §7 的列表上限约束。
- 简要上下文里只带上一回合的摘录，用于保持语气连续。
- 验收：第 300 回合的简要上下文不超过第 10 回合的 1.5 倍（`ACCEPTANCE.md` §5）。

## 8. 撤销、改写、追溯

| 玩家说 | 调用 | 效果 |
|---|---|---|
| 撤销 / 刚才不算 | `undo-turn` | 状态回到上一回合结束时；turn − 1；被撤销的回合留档，标记为已撤销，不进入摘要和任何人的知识 |
| 刚才不算，改成 Y | `commit-turn`，带 `replaces_turn: N`，行动模式按 Y 判断 | 在同一事务里撤销第 N 回合并应用 Y；`N` 必须是当前最后一个有效回合 |
| 其实…… | `commit-turn`，`action_mode: "rewrite"` | 只允许追溯事实（来源为追溯）与 `player_update`；其余操作按“继续”的规则处理；turn +1 |

- 可以连续撤销，最多退到本次读档或开局的那一回合。存储方式由实现者决定（每回合快照、逆操作都行），但必须有上限，并且在读档时重置。
- 追溯事实与已有事实冲突时（按事实键），提交被拒，并指出冲突的是哪条事实。

## 9. 存档、读档与续玩

### 9.1 自动保存与续玩

- 每次成功提交就是一次持久化；会话跨对话存在。
- 新对话里说“继续上次 / 恢复”：调用 `list-sessions`，只有一个最近会话时直接接上，多个时列出让玩家选；然后用 `get-context`（完整深度）接续。
- “恢复”有歧义时，三选一：恢复上次会话 / 读取某个存档 / 解除暂停（当前局在暂停中时）。

### 9.2 `save-slot`

输入：`session_id`、`request_id`、`expected_revision`、`name`（可省略）、`overwrite`（默认 false）。

- 省略名字：存到当前槽，也就是本局最近一次保存或读取的槽；没有当前槽时自动命名为“世界名-第N回合”，并在回执里告知。
- 名字已被占用，且不是本局的当前槽：返回 `SLOT_CONFLICT`，`reason: "exists"`。模型问玩家是否覆盖，确认后带 `overwrite: true` 重交。
- 本局的当前槽在别的对话里被写过（槽的版本比本局记住的新）：返回 `SLOT_CONFLICT`，`reason: "changed_elsewhere"`。模型给玩家三个选项：A 读取最新 / B 另存为新名 / C 取消。
- 成功后，槽成为本局的当前槽，并返回槽的新版本。

### 9.3 `load-slot`

- 创建一个新的会话副本，原存档不变；新会话的当前槽就是这个存档。
- 边界、暂停、事件、冷却、语态、偏好原样恢复，不重掷任何随机。
- 返回完整上下文和 `resume`：最近的章节摘要、最近 3 个回合摘要、上一回合的摘录、`open_action`。
- 模型的回执：先写“已读取「名称」·第 N 回合”，再写两三句前情，然后从未决动作的前一刻接着写，不重复开局那三段。

### 9.4 导出与导入

- `export-save`：输入会话或存档名，写到数据目录的 `exports/`，或写到用户明确给出的路径，返回文件路径。导出文件带完整性校验值，用来发现截断和损坏；它是交换格式的数据校验，不是 `DESIGN_DECISIONS.md` D9 所禁止的治理锁。
- `import-save`：接受文件路径或内联 JSON。先完整校验，任何错误都不写入。版本较旧时先备份再迁移，较新时返回 `UNSUPPORTED_VERSION`。成功后得到一个新会话，可选同时写入一个存档槽。

## 10. 安全处理

- **边界**：`set-boundary` 加 `add` 或 `remove`。模型把玩家的话映射到内容标签表（`DATA_CONTRACTS.md` §8.4）；映射不上的，记为 `custom` 并保留原话。
  - 带标签的边界由引擎强制：任何 `content_tags` 与之冲突的提交返回 `SAFETY_BLOCK`。
  - `custom` 边界引擎无法自动匹配，它们出现在每一次上下文里，由模型遵守、由评审检查。
- **暂停**：`set-safety` 加 `paused: true`，立即生效。
  - 暂停期间，带亲密标签或冲突类标签（暴力、胁迫、羞辱、身体伤害）的提交被拒，非亲密剧情可以继续。
  - 暂停只由玩家解除（“继续”“恢复”“解除暂停”）。解除后不自动接着升级：从停下的那一点重新开始，NPC 的回应重新判断。
  - “换个场景”：保持暂停，同时推进到一个新的非亲密场景。
- **年龄**：新角色（包括自定义世界里的角色和玩家角色）年龄 < 18 或缺失，提交被拒。
- **亲密提交的结构检查**：见 `DATA_CONTRACTS.md` §6。

## 11. 故障恢复速查

提交被拒见 §5.1，存档槽冲突见 §9.2，开局约束无法满足（`NO_MATCH`）与自定义世界校验失败见 §4.3。其余情况：

| 情况 | 处理 |
|---|---|
| 宿主工具调用超时、没有输出、输出不是 JSON | 用同一 `request_id` 重试最多 3 次；仍失败则运行 `doctor`，并用一句话告诉玩家 |
| `IDEMPOTENCY_CONFLICT` | 这个 `request_id` 之前已经成功过（常见于超时后改了内容再重交）。先 `get-context` 确认上一次是否已经生效，再决定是否需要用新的 `request_id` 补交；不能把同一回合写两次 |
| `NOT_FOUND`（存档或会话） | 不猜名字：用 `list-slots` 或 `list-sessions` 列出实际存在的，让玩家选 |
| `RUNTIME_UNSUPPORTED` | 告诉玩家需要的 Python 版本；不自动安装、不改系统环境 |
| `DATA_DIR_UNAVAILABLE` | 按错误里的建议选一个可写目录（`--data-dir` 或环境变量），见 `SKILL_PACKAGING.md` |
| `CONTENT_ERROR`（内置内容） | 停止开局，报告文件、条目与字段；不跳过坏条目继续 |
| `UNSUPPORTED_VERSION` | 说明存档来自更新的版本，建议升级 Skill；不改动存档 |
| `INTERNAL_ERROR` | 状态不变；告诉玩家日志位置，并建议导出存档 |

在任何失败下都不能留下半写的会话、空存档槽或错误的成功回执。
