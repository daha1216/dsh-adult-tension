# 需求追踪

对每一项 P0 需求，本表列出三件事：语义写在哪里（规范），哪个阶段首次实现（`DELIVERY_PLAN.md`），用什么证明它做完了（`ACCEPTANCE.md`）。

用法：

- 每个阶段收尾时，把本阶段涉及的行抄进 `PROGRESS.md`，并在每行填上证据的实际位置：测试名、报告路径或记录文件。
- 本表只是索引，不产生新要求。它与正文不一致时，以正文为准，并在 `PROGRESS.md` 记下这处不一致。
- 第一列用 `PRODUCT_SPEC.md` §4 里的功能名，方便对照检索。
- 证据列的写法：
  - “剧本 N”指 `ACCEPTANCE.md` §6.4 的第 N 条剧本。
  - “§2 某组”指 `ACCEPTANCE.md` §2 里的那一组测试。
  - “自动测试：……”是 `ACCEPTANCE.md` §2 没有逐条列出、但必须有的行为测试（`ACCEPTANCE.md` §2 开头要求每项 P0 至少有一个自动测试或剧本覆盖），冒号后面写它要验证什么。
- 阶段列写两个数字时，前一个阶段做基本能力，后一个阶段补齐。

缩写：PS = `PRODUCT_SPEC.md`，NR = `NARRATIVE_RULES.md`，DD = `DESIGN_DECISIONS.md`，DC = `DATA_CONTRACTS.md`，RP = `RUNTIME_PROTOCOL.md`，CB = `CONTENT_BIBLE.md`，SP = `SKILL_PACKAGING.md`，ST = `SKILL_TEMPLATE.md`，AC = `ACCEPTANCE.md`，AR = `ARCHITECTURE.md`。
